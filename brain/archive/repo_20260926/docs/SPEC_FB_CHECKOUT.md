# 🛒 สเปค: หน้าสั่งซื้อสำหรับลูกค้าจาก Facebook (web checkout)

> **นัทเคาะเอง 19 ส.ค. 2026** · เลขาถอดจากบทสนทนา **ไม่ได้ตีความเพิ่ม**
> 🅿️ **สถานะ: ยังไม่เริ่มทำ** — นัทตั้งเป้า 3 งานให้เสร็จก่อนศุกร์ 21 ส.ค. (ออโตเมชั่นสั่งผัก · เตรียมเมนู MP ล่วงหน้า · ยิงโฆษณา) · **อันนี้เข้าคิวหลังจากนั้น**

---

## ปัญหาที่แก้

> **นัทพูดเอง:** *"ฉันกำลังคิดว่ามันอาจจะยากเกินไปสำหรับลูกค้าหรือเปล่า เวลาเราโฆษณาผ่าน Facebook แล้วก็จะเป็นลิงก์ให้ลูกค้ากดคลิกเข้าไปที่เว็บไซต์ แล้วก็กดเข้าไปที่ LINE ของเราอีกทีนึง"*

**ทางที่ใช้อยู่ = 4 ด่าน:** เห็นแอด → เข้าเว็บ → หาปุ่ม LINE → แอดเพื่อน → เปิด LIFF → สั่ง
ทุกด่านมีคนหาย · และ **Meta วัดไม่ได้ว่าแอดทำเงินได้จริงกี่บาท** (เห็นแค่ "คนคลิก")

## ทางที่เคาะแล้ว

```
แอด FB/IG → หน้าเดียวจบ (เห็นโปร + สั่ง + จ่าย)  ← ปิดการขายตรงนี้
          → หน้าขอบคุณ: ติดตามออเดอร์ + ชวนแอดไลน์
```

### กติกาที่นัทเคาะ
1. **ล็อกอินด้วย LINE เป็นหลัก · ไม่ทำ Google**
   > **นัทพูดเอง:** *"ตอนกดสั่งก็ให้ลูกค้า login ผ่าน LINE ดีกว่าเนาะ ถ้าเกิดผ่าน Google มันไม่น่าจะไม่ค่อยได้ใช้อะไร"*
   เหตุผล: อีเมลเอามาทำอะไรต่อไม่ได้ (เราไม่ได้ทำ email marketing) · **ช่องทางซื้อซ้ำของร้าน = LINE**
2. **Guest ยังต้องมี** เป็นทางเลือกสำรอง (คนกลัวล็อกอิน / เปิดจากคอมที่ไม่มีไลน์) — กรอกชื่อ/เบอร์/ที่อยู่ แล้วซื้อจบ
3. **ขายชุดเดียว ไม่ใช่ทั้งเมนู** — ยิ่งให้เลือกเยอะยิ่งไม่กด (เริ่มที่เซ็ตทดลอง)
4. **ออเดอร์ลงตารางเดิม** ครัว/แมสไม่ต้องรู้ว่ามาจากไหน

---

## 🔑 กลไกสำคัญ: LINE Login แบบชวนเป็นเพื่อนพร้อมกัน

LINE Login บนเว็บตั้งให้ **prompt เพิ่มเพื่อนตอน login** ได้ → ลูกค้ากดปุ่มเดียวตอนเช็คเอาท์ เราได้ทั้ง **`line_uid` + เป็นเพื่อนใน OA**
**= ได้สิ่งที่ guest checkout ทำให้เสียไป กลับมาครบ โดยไม่ต้องเพิ่มด่านก่อนขาย**

⚠️ **LINE Login คนละช่องกับ Messaging API** — ช่องส่งข้อความยังติดอยู่กับ Hato แต่ **LINE Login เปิดใหม่เองได้ ไม่ต้องรอ Hato** (เรื่องนี้ไม่บล็อกกัน)

## ✅ ของที่มีอยู่แล้ว (ไม่ต้องสร้างใหม่)

| ต้องใช้ | มีแล้วที่ไหน |
|---|---|
| คิดค่าส่งตามระยะขับจริง · ตะกร้า · โปรโค้ด · อัพสลิป · ตัดสต็อก | `liff_customer.html` (ทำงานอยู่จริง) |
| รวมลูกค้าซ้ำด้วยเบอร์โทร | `resolveCanonicalCustomer` (u0.4.41) |
| ช่องเก็บที่มาของลูกค้า | `customers.source_first` · `source_campaign` · `source_ad_id` · `email` · `line_uid` |
| ช่องเก็บที่มาของออเดอร์ | `orders.source` · `orders.source_campaign` |

**→ ไม่ต้องแก้โครงฐานข้อมูลเลย** งานจริงคือ **ถอด "ต้องล็อกอิน LIFF" ออก แล้วใส่ฟอร์มแทน**

## 🔨 ของที่ยังไม่มี ต้องทำใหม่

1. **หน้า checkout เว็บ** (ไม่ผูก LIFF) + ปุ่ม "สั่งด้วย LINE (เร็วกว่า)" ด้านบน + ฟอร์ม guest ด้านล่าง
2. **LINE Login channel สำหรับเว็บ** + เปิด prompt เพิ่มเพื่อน
3. **หน้าติดตามออเดอร์แบบ guest** — เปิดด้วย `เลขออเดอร์ + เบอร์โทร` (ไม่ต้องล็อกอิน)
4. **เก็บ UTM → `orders.source_campaign`** ตอนสร้างออเดอร์ (ตัวปิดลูป "แอดทำเงินกี่บาท")

## ⚠️ ความเสี่ยงที่ต้องกันไว้ตั้งแต่ออกแบบ
- **2 ทางสั่ง = 2 ที่พัง** — ตรรกะราคา/ค่าส่ง/สต็อก ต้องใช้ชุดเดียวกัน ห้ามเขียนซ้ำคนละที่
- **ลูกค้าซ้ำ** — คนเดิมสั่ง guest วันนี้ แล้วแอดไลน์พรุ่งนี้ ต้องรวมร่างด้วยเบอร์ (มีตัวช่วยแล้ว แต่ต้องเรียกใช้)
- **สลิป/เงิน** — ต้องผ่านทางเดียวกับ LIFF (`payment_status` + `slip_url`) ไม่งั้นหน้าตรวจสลิปของแอดมินจะไม่เห็น
