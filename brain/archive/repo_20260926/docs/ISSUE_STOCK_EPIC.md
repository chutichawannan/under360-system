# 📦 มหากาพย์การตัดสต็อค — ไล่ทั้งเส้นทาง ตั้งแต่ลูกค้ากดสั่งจนของถึงมือ

> เปิดโดย U-track · 14 ส.ค. 2569 · **นัทสั่งเปิดเอง**
> *"ช่วยเปิดเป็น issue ใหญ่ ตั้งชื่อว่า มหากาพย์การตัดสต็อค ที่มีปัญหาครบทุกส่วน"*
>
> เอกสารนี้ **ไม่ใช่รายการงาน** — เป็นการไล่ว่า "ของ 1 กล่อง" เดินทางผ่านมือใครบ้าง
> แล้วตรงไหนที่ตัวเลขกับของจริงหลุดจากกันได้ · แก้ทีละจุดโดยไม่เห็นทั้งเส้น = ย้ายปัญหาไปที่อื่น

## 🎯 ทำไมเรื่องนี้ถึงยาก (แก่นของปัญหา)

ระบบเรามี **เลข 3 ชุดที่หมายถึงคนละอย่าง** แต่ถูกใช้ปนกัน:

| เลข | ความหมายจริง | ใครเป็นเจ้าของ |
|---|---|---|
| `stock_total` | **ลูกค้าสั่งได้อีกกี่กล่อง** | ระบบขาย |
| `actual_stock` | **ครัวนับได้กี่กล่อง ณ ตอนนับ** | ครัว |
| ของในตู้จริง | **ความจริง** | ตู้เย็น |

ทั้ง 3 อันนี้ **ไม่มีวันตรงกันตลอดเวลา** และนั่นไม่ผิด — สิ่งที่ผิดคือ **ไม่มีใครรู้ว่าตอนไหนมันควรตรงกัน**

## 🔴 ปัญหาที่พบแล้ว (ยืนยันจากโค้ด/ข้อมูลจริง)

### 1. แอดมินสั่งแทนลูกค้า = ไม่ตัดสต็อกเลย
`operation_hub.html` เรียก `adjust_stock` แค่ 2 จุด และ **ทั้งคู่อยู่ในเรื่องยกเลิก/กู้คืน**
→ กิ๊ฟกดสั่งแทนลูกค้า 10 กล่อง = **ระบบยังคิดว่าของครบเหมือนเดิม**
→ ลูกค้าคนถัดไปสั่งได้เกินของที่มี · ครัวเปิดใบมาแล้วของไม่พอ
**นี่คือรูใหญ่ที่สุดที่ยังเปิดอยู่** (ออเดอร์ที่กิ๊ฟกดมีทุกวัน)

### 2. ครัวกรอก "ผลิตได้จริง" = เขียนทับ ไม่ใช่บวกเพิ่ม
หน้าครัวตั้ง `stock_total = ตัวเลขที่กรอก` ตรงๆ
→ ถ้าครัวกรอกตอน 9 โมงว่าผลิตได้ 20 แล้วมีคนสั่งไป 3 กล่องตอน 10 โมง
→ ครัวกลับมากรอกซ้ำตอนบ่ายว่า 20 (เพราะนับของที่ผลิตได้) = **ยอดขาย 3 กล่องหายไปจากระบบ**
ครัวไม่ได้ทำผิด — ครัวรายงาน "ผลิตได้เท่าไหร่" แต่ระบบเอาไปใช้เป็น "ขายได้อีกเท่าไหร่"

### 3. ยกเลิกออเดอร์แล้วสต็อกไม่คืน → **แก้แล้ว** `2ad2510`
ยกเลิก = คืนสต็อก · กู้คืน = ตัดกลับ · ทั้ง 2 ทางขึ้นข้อความบอกว่าคืนกี่กล่อง
⚠️ **แต่ครอบแค่การยกเลิกจากหน้าออเดอร์** — ยังไม่ครอบ: ยกเลิกรอบจากหน้าแพลนเมนู · ลูกค้าขอข้ามรอบเอง

### 4. ออเดอร์ที่ไม่มีใครจ่าย/ไม่มีใครส่ง = สต็อกถูกตัดค้างตลอดกาล
ทุกออเดอร์เกิดมาเป็น `confirmed` ทันที **ไม่มีสถานะ "ยังไม่ยืนยัน"**
→ ตัดสต็อกตั้งแต่วินาทีที่กดสั่ง
→ ถ้าลูกค้าไม่โอน ไม่มีอะไรคืนสต็อกเลย · **ไม่มี cron ไหนเก็บกวาด** (`vercel.json` มี cron ตัวเดียว = แจ้งเตือน Meal Plan)
**วัดแล้ว: 18 ใบ เลยวันส่งไปแล้วแต่ยังไม่จ่าย** — ของพวกนี้กินสต็อกอยู่โดยไม่มีใครได้กิน

### 5. ครัวจัดของจริงไปแล้ว แต่ระบบยังไม่ตัด / ตัดแล้วแต่ยังไม่ได้จัด
ตอนนี้ **"ตัดสต็อก" ผูกกับ "ลูกค้ากดสั่ง" ไม่ได้ผูกกับ "ของออกจากตู้"**
→ 2 เหตุการณ์นี้ห่างกันได้เป็นวัน และสลับลำดับกันได้ทั้งสองทาง

## 🧭 ทางแก้ที่เสนอ — แยก "จอง" ออกจาก "ตัดจริง"

**หลักการเดียว: สต็อกลดตอนของออกจากตู้ ไม่ใช่ตอนลูกค้ากดปุ่ม**

```
ลูกค้ากดสั่ง / แอดมินสั่งแทน
        ↓  จอง (reserve) — ยังไม่ตัดของจริง
   ครัวจัดของลงกล่อง
        ↓  ตัดจริง (commit) — ของออกจากตู้แล้ว
        แมสรับไปส่ง
```

| เหตุการณ์ | ตอนนี้ | ที่ควรเป็น |
|---|---|---|
| ลูกค้ากดสั่ง | ตัดทันที | **จอง** |
| แอดมินสั่งแทน | ไม่ทำอะไร ❌ | **จอง** |
| ยกเลิก / เลยกำหนดไม่จ่าย | คืน (เพิ่งแก้) | **ปล่อยการจอง** |
| ครัวกดจัดของเสร็จ | ไม่ทำอะไร | **ตัดจริง** |
| ครัวนับสต็อกใหม่ | เขียนทับทุกอย่าง ❌ | **ตั้งของจริง แล้วคำนวณยอดขายได้ใหม่จากการจองที่ค้าง** |

**ลูกค้าสั่งได้อีก = ของในตู้ − ที่จองไว้แล้ว**
ครัวนับใหม่เมื่อไหร่ก็ไม่ทำยอดขายหาย เพราะ "จอง" เก็บแยกคนละที่กับ "ของในตู้"

## ⚠️ สิ่งที่ต้องเคาะก่อนลงมือ (ถามนัท)

1. **การจองหมดอายุเมื่อไหร่** — ไม่จ่ายภายในกี่ชั่วโมงให้ปล่อยของคืน? (ถ้าไม่มีเวลาหมดอายุ ปัญหาข้อ 4 จะกลับมา)
2. **ครัวกดตรงไหนว่า "จัดของเสร็จแล้ว"** — ใช้ปุ่มสถานะที่มีอยู่ หรือทำปุ่มใหม่
3. **ของที่จองแล้วยังไม่จ่าย ให้ลูกค้าคนอื่นแย่งได้ไหม** — ถ้าได้ ใครมาก่อนได้ก่อน / ถ้าไม่ได้ ต้องมีเวลาหมดอายุ

## 🚫 สิ่งที่ห้ามทำระหว่างนี้

- **ห้ามไล่แก้ตัวเลขในฐานข้อมูลด้วยมือ** (นัทสั่งเอง 13 ส.ค.: *"ไม่ต้องการมาแก้ปัญหาที่ปลายเหตุ"*)
