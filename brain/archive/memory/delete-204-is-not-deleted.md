สั่งลบแถวผ่าน REST ด้วย anon key แล้วได้ **204 No Content** = "คำสั่งถึงเซิร์ฟเวอร์" ไม่ได้แปลว่า "ลบไปแล้ว" — ถ้า RLS ไม่อนุญาต แถวยังอยู่ครบ **โดยไม่มี error**

เกิดจริง 8 ก.ย. 2026: ห้อง M รายงานว่าลบแถวทดสอบใน `web_events` แล้ว 2 ครั้ง ทั้งที่ยังอยู่ · ห้อง 06 จับได้ตอน query ซ้ำ

**Why:** เป็นตระกูลเดียวกับ "เครื่องมือคืนผลลวงโดยไม่มีอะไรแดง" ที่ทำให้รายงานผิดแล้วคนอื่นเอาไปตัดสินใจต่อ

**How to apply:** หลัง DELETE/UPDATE ทุกครั้ง **นับแถวซ้ำ** (`Prefer: count=exact`) ก่อนบอกว่าเสร็จ · เกณฑ์เดียวกับ [[verify-what-human-sees]] และ [[working-tree-is-stale]] — สถานะสำเร็จไม่ใช่หลักฐาน ผลลัพธ์ที่ query ซ้ำได้ต่างหากที่ใช่
