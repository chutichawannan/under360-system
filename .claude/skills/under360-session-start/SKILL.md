# Under360 — Session Start Protocol

**กฎเหล็ก: ห้ามแก้โค้ด/ตอบเรื่อง state ของระบบ ก่อนอ่าน context ครบ**

## 1. อ่านไฟล์ context ก่อนเสมอ (ตามลำดับ)
1. `CLAUDE.md` (root ของ repo) — **กฎถาวร** (conventions/stack/credentials/แบรนด์/ตาราง DB)
2. `PRD.md` (root) — **สเปคงานที่กำลังทำอยู่ตอนนี้แผ่นเดียว** · อะไรที่ไม่อยู่ในแผ่นนี้ = ไม่ทำ (เปลี่ยนงาน = เขียนทับแผ่นนี้)
3. `TODO.md` (root) — งานค้างทุก track + หัวข้อ "🔴 นัทต้องทำ"
4. `docs/UNDER360_MASTERNOTE_v*.md` — ยุทธศาสตร์/backlog (เอาเวอร์ชันสูงสุด · **ไม่ใช่ไฟล์สั่งงาน**)
5. `docs/UNDER360_HISTORY.md` — timeline ความสำเร็จ + เลขเวอร์ชันปัจจุบัน (u/m/a/doc)

> 📁 ไฟล์ตระกูล MASTERNOTE/HISTORY อยู่ใน `docs/` และ **ถูก gitignore** (doc-flow working files) — ไม่เจอใน GitHub เป็นเรื่องปกติ

ถ้าไม่เจอไฟล์เหล่านี้ → **ถามหา 1 ครั้ง แล้วหยุดรอ** อย่าเริ่มงานโดยเดา

## 1.5 🔒 จองงานก่อนทำ — กันทำซ้ำข้ามห้อง (บังคับ · นัทสั่ง 5 ส.ค. 2026)

> **ที่มาของกฎ:** หลาย session รันขนานกัน แล้ว **TODO.md ขีดออกช้ากว่าความจริง 1-2 วันเสมอ** → ห้องใหม่หยิบงานที่คนอื่นทำเสร็จแล้ว (เกิดจริงหลายรอบ: รูปการ์ดหน้าโฮม · 1000-cap · KPI ใน OH)
> **และในทางกลับกัน** งานที่ "มีคนถืออยู่แต่ติดบล็อกเกอร์" ก็ค้างเงียบเป็นสัปดาห์ (รายงาน Hato ค้าง 9 วัน เพราะรอนัทฟอเวิดเมล ไม่มีใครรู้)

**hook `SessionStart` ยิงบอร์ดเข้า context ให้อัตโนมัติแล้ว** (`scripts/cc_board.ps1`) — ไม่ต้องไปหาเอง แค่**อ่านตอนต้น session**

**ก่อนลงมืองานใหม่ทุกชิ้น:**
1. ดูรายการ `[🔒 งานที่ห้องอื่นถืออยู่]` จาก hook → **เจอคนจองแล้ว = ไม่ทำ** ให้โพสต์ถามเจ้าของใน `session_messages` แทน
2. ไม่มีใครจอง → **จองก่อน** แล้วค่อยลงมือ:
```bash
curl -s -X POST "https://zdartbvhbvqlwzwyyiia.supabase.co/rest/v1/work_claims" \
  -H "apikey: $ANON" -H "Authorization: Bearer $ANON" -H "Content-Type: application/json" \
  -d '{"task":"ชื่องานสั้นๆ","room":"u","files":"liff_customer.html"}'
```
3. เสร็จแล้ว → `PATCH` เป็น `status=done` **พร้อม `evidence`**

**⚠️ กติกา "เสร็จ" (ข้อนี้สำคัญกว่าข้ออื่น):** ห้ามปิดงาน/ขีด TODO ด้วยคำบอกเล่า — ต้องมี **หลักฐานที่คนอื่น query ซ้ำได้** เช่น *"HS- สุ่ม 40 ใบ มี order_items 40/40"* · *"menu_items รูปจาก Storage เรา 423/423 ไม่มี Hato CDN"*
เหตุผล: เอกสารในโปรเจคนี้ **stale เร็วกว่าที่คิดเสมอ** — เชื่อ DB/ไฟล์จริง อย่าเชื่อบรรทัดใน TODO

## 2. สรุปให้นัทดู 5 บรรทัด ก่อนเริ่ม
- เวอร์ชันปัจจุบัน: u? / m? / a?
- งานที่ค้างอยู่ 3 อันดับแรก
- SQL ที่ยังไม่ได้รันใน Supabase (ถ้ามี)
- ไฟล์ที่ยังเป็น mock data
- คำถาม: "วันนี้จะทำข้อไหน?"

## 3. บริบทตัวคน (สำคัญกับวิธีตอบ)
- นัท **ไม่ใช่ developer** — อ่านโค้ดได้บ้าง แต่ไม่เขียนเอง
  → อธิบายเป็นภาษาคน ไม่ใช่ jargon · ให้ผลลัพธ์ที่รันได้จริง ไม่ใช่ทฤษฎี
- **ตอบภาษาไทย** เสมอ (technical term เป็นอังกฤษได้)
- **"ปรับได้เลย" = ทำเลย ห้ามถามซ้ำ**
- ถามกลับได้เฉพาะเมื่อเป็น **fork ระดับ architecture** เท่านั้น
- นัทส่งข้อความ multi-part ในทีเดียว → **ตอบให้ครบทุก part** อย่าตกข้อ
- ถ้า ambiguous → เลือกทางที่ง่ายที่สุด ทำไปก่อน แล้วแจ้งทีหลัง

## 4. 📬 กล่องจดหมาย (inbox ข้ามห้อง — ตอบกันเองแบบประหยัด · นัทออกแบบ 1 ส.ค. 2026)
> ให้ห้องต่างๆ "ตอบกันเอง" ได้ โดย**โหลดสมองตอบเฉพาะตอนมีจดหมายจริง** — บุรุษไปรษณีย์ (`under360-postman`, รันใน 1 terminal) คอยไล่ดูบอร์ดแล้ว ping เฉพาะห้องที่มีจดหมาย · ห้องที่ไม่มีจดหมาย = ไม่ตื่น = ไม่เผา token

**room id ของตัวเอง (ดูจากชื่อ session):** `u`=U-track · `m`=M-track · `eath`=05 LINE OA / 06 FB Ads · `f`=08 F-track · `migrate`=P-track/Migrate · `niw`=12 นิว · `tiang`=10 เตียง · `a`=04 A-track / 09 widget · `rnd01`=R&D 01 · `keng`=พี่เก่ง · `fah`=ฟ้า · `ploy`=ห้องพลอย · `cc`=Command Center

**ทำเมื่อ (ก) เปิด session ใหม่ (ข) ได้ ping "📬 มีข้อความใหม่":**
1. อ่านบอร์ด: `GET session_messages?room=eq.{ROOM}&order=created_at.desc&limit=15` (creds SB/anon ใน CLAUDE.md)
2. มีจดหมายค้างไหม = **ข้อความล่าสุดไม่ใช่ของห้องเราเอง** (เป็นของนัท/ห้องอื่น) และเรายังไม่ตอบ
3. มี → ตอบสั้นๆ **POST ลงบอร์ด** `room={ROOM}` (`sender`=ชื่อห้อง, `role`=claude) ผ่าน `curl --data-binary @file` (กัน escape ไทย)
4. ไม่มี → ไม่ต้องทำ/ไม่ต้องโพสต์
- ⚠️ ตอบเฉพาะจดหมายที่ถึงห้องเราจริง · **ตอบจบใน 1 รอบ แล้วรอ ping ใหม่** (ห้ามตอบวนกันเอง) · เรื่องที่ต้องนัทตัดสิน = ไม่ตอบเอง ยกให้นัท
