# §1 ตัวเลขฐาน — ใช้เทียบทุกครั้ง

**ยอดขายปกติเมื่อไม่มีบรอดแคสต์:** ประมาณ **฿6,500 – ฿9,000/วัน** (ส.ค. 2026 · ตัดใบทดสอบและใบยอด ฿0 แล้ว)
→ เวลาวัดผลบรอดแคสต์ ให้เทียบกับ **ค่าเฉลี่ย 3 วันก่อนยิง** ไม่ใช่เทียบกับวันเดียว (ยอดรายวันแกว่งแรงมาก ฿2,818 – ฿11,791 ในสัปดาห์เดียวกัน)

**โควตา LINE:** ฟรี **35,000 ข้อความ/เดือน · รีเซ็ตวันที่ 1**
**1 คน = 1 ข้อความ ไม่ว่าจะส่งกี่บับเบิล** (พิสูจน์แล้ว: 3,916 คน → โควตาขยับ 3,974)
→ **บับเบิลไม่มีต้นทุน คนมีต้นทุน** · อย่าประหยัดบับเบิล ให้ประหยัดคนที่ยิงหา

## 📅 แผนใช้โควตาทั้งเดือน (นัทเคาะเอง 4 ก.ย. 2569)

> *"1 เดือนเราบรอด 4-5 ครั้ง ตามจำนวนสัปดาห์ที่มีอยู่แล้ว · **แล้วเราก็ไปเทให้หมดหน้าตักสิ้นเดือนก่อนรีเซ็ต**"*

- **แบ่งโควตาเป็น 5 ก้อน** — 35,000 ÷ 5 ≈ **7,000/รอบ** ยิงสัปดาห์ละครั้งตามจำนวนสัปดาห์ในเดือน
- **สิ้นเดือน: เทที่เหลือให้หมดก่อนรีเซ็ตวันที่ 1** — โควตาไม่ทบไปเดือนหน้า **เหลือ = ทิ้งฟรี**
- ❌ **ห้ามยิงหมดหน้าตักในรอบเดียวต้นเดือน** — 29 ส.ค. ใช้ 9,695 รอบเดียวเหลือก้น 89 → **ทั้งเดือนยิงได้แค่ครั้งเดียว**
- รอบสิ้นเดือนที่เททิ้งท้าย = ที่ที่เหมาะกับ **กลุ่มเย็น** (หายเกิน 1 ปี 1,716 คน) — ยิงเพื่อปลุก ไม่ได้หวังยอด เสียโควตาที่จะทิ้งอยู่แล้ว

⚠️ **เช็คโควตาจริงทุกครั้งก่อนวางแผน ห้ามเชื่อตัวเลขในเอกสาร**
```bash
node -e "..."   # action:'quota' ที่ /api/line-campaign → คืน {type,value} + ใช้ไปเท่าไหร่
```
🔴 **4 ก.ย. 2569 เจอของจริง: แพ็กเกจตกจาก 35,000 → limited 300** (29 ส.ค. หน้าจอยังขึ้น 25,216/35,000)
**นี่คือเหตุผลที่ต้องถาม LINE เอง ไม่ใช่อ่านตัวเลขที่จดไว้** — แพ็กเกจเปลี่ยนได้เงียบๆ ตอนขึ้นเดือน

**ตัวเลข LINE OA (30 วัน):** เพื่อน ~53,000 · **reach จริง 23,246** · **บล็อก 25,911** · active <90 วัน = **144 คน**
→ ฐานส่วนใหญ่คือคนที่ไม่อ่านแล้ว **การยิงกว้างคือการเผาโควตา ไม่ใช่การเข้าถึง**

## สิ่งที่ข้อมูลบอกจริง (แยกจากที่เราเดา)

**✅ ยืนยันแล้ว — โปรที่ไม่ต้องทำอะไรเลย ชนะขาด**
WELCOME50 + FREESHIP = **122 ครั้ง** มากกว่าโค้ดพิมพ์เองทุกตัวรวมกัน (39)

**✅ ยืนยันแล้ว — บังคับให้ลูกค้า "ทักแอดมิน" ก่อน = ตาย**
SALMON = 0 ทั้งที่ของแถมดี · **อย่าออกแบบโปรที่ต้องคุยกับคนก่อนถึงจะได้**

**⚠️ ยังไม่ยืนยัน — "โค้ดพิมพ์เองใช้ไม่ได้ผล"**
🔴 **ผมเคยสรุปกับนัทเมื่อ 30 ส.ค. ว่า "0 คนใช้" — ผิด 2 ชั้น: ดูเร็วไป 1 วัน (ของจริง 1+1) และสรุปกว้างเกินหลักฐาน** — เพราะ **FREEWEEKDAY มี 11 ครั้ง และมาจากบรอดแคสต์เหมือนกัน**
ความต่างที่น่าจะใช่ (ยังเป็นสมมติฐาน ห้ามเอาไปอ้างเป็นข้อเท็จจริง):
- **ชื่อโค้ดบอกของที่ได้เลย** — "FREEWEEKDAY" อ่านปุ๊บรู้ว่าได้อะไร · "WEEK120"/"NEW200" ต้องแปลก่อน
- **ไม่มีขั้นต่ำสูง** — WEEK120/NEW200 ตั้งขั้นต่ำ ฿890 ซึ่งตัดออก **29% ของออเดอร์ทั้งหมด**
- **เวลา** — WEEK120/NEW200 เพิ่งออก 1 วัน · โปรถึง 7 ก.ย. **ยังวัดไม่จบ**

**→ สิ่งที่ต้องทำ ไม่ใช่สรุป แต่คือทดลอง:** รอบหน้าลองใส่ `show_suggested` ให้โค้ดแคมเปญ 1 ใบ แล้วเทียบกับใบที่ให้พิมพ์เอง
⚠️ ข้อแลกเปลี่ยนที่ต้องบอกนัทก่อนทำ: **`show_suggested` โผล่ให้ทุกคนที่เข้าหน้าจ่ายเงิน ไม่ใช่เฉพาะคนที่ได้บรอดแคสต์** = ใช้เยอะขึ้นแต่วัดผลไม่แม่น และแจกส่วนลดให้คนที่จะซื้ออยู่แล้ว

**🔧 ทางออกที่ถูกที่สุด (ขอไปที่ห้อง U แล้ว 27 ส.ค. ยังไม่เสร็จ):**
**"แท็กแคมเปญชั่วคราว"** — ติดแท็กที่ตัวลูกค้าที่เรายิงไปให้ + มีวันหมดอายุ → เขาเปิดแอปมาเห็นราคาลดเลย **ไม่ต้องพิมพ์ · คนอื่นไม่เห็น · วัดผลได้แม่น**
นี่คือกลไกที่แก้ปัญหานี้ตรงจุดที่สุด และนัทเคาะแล้วว่าเอา — **ทวงต่อจนได้**

# §8 ด่านเมนูประจำสัปดาห์ (นัทสั่ง "hook ไว้" · 4 ก.ย. 2569)

> **นัทพูดเอง:** *"กฎของเมนูประจำสัปดาห์ คือเราต้องวนเมนูไม่ซ้ำเท่านั้น hook ไว้ ยังไงก็ต้องได้เมนูใหม่ ถ้าไม่ได้ต้องทวง"*

```bash
node scripts/check_weekly_menu.mjs 2026-09-07     # exit 1 = ห้ามเปิดขาย ห้ามยิง
```
ตรวจ ① ห้ามซ้ำ 90 วัน ② มีรูป ③ โภชนาการครบ ④ D จับคู่ S ⑤ ราคาขั้นต่ำ

**ทั้ง 2 เรื่องที่เกือบหลุดสัปดาห์นี้ ด่านจับไม่ได้เลยสักอัน — คนจับได้ทั้งคู่**
→ **ด่านจับ "กฎ" · เตียงจับ "ตา" · นิวจับ "ความสมเหตุสมผลของข้อมูล"**

## 🎓 บทเรียนใหญ่ — **"ไม่มีข้อมูล" ≠ "ข้อมูลไม่มีอยู่จริง"**
ผมสรุปว่า *"ทั้งคลังมีโภชนาการ 55 เมนู · จัดชุดไม่ซ้ำเป็นไปไม่ได้"* · นัทตอบประโยคเดียว *"เป็นไปไม่ได้ที่จะไม่มีเมนูให้วน"* แล้วส่งลิงก์ชีทมา
ชีท `All menu+แพลนเมนูอาทิตย์ถัดไป` (พลอยเป็นเจ้าของ) แท็บ Special 2026 มี **187 เมนูโภชนาการครบ · DB มี 40 → 141 ตัวไม่เคยถูกเติมลง DB** และทุกตัวมีรูปใน DB แล้ว
พอนับชีทด้วย: คู่ข้อมูลครบ **12 → 47** · คู่ไม่ซ้ำ 90 วัน **0 → 8**
→ **ผมดูแต่ DB แล้วประกาศว่าเป็นเพดานของร้าน ทั้งที่มันคือเพดานของการ import**
→ **กฎใหม่: ก่อนบอก "ทำไม่ได้เพราะไม่มีข้อมูล" ต้องถามก่อนว่า "ข้อมูลอาจอยู่ที่อื่นไหม"** — เจ้าของร้านรู้ว่าของอยู่ไหน เราไม่รู้

## 🎓 คู่กัน — ข้อมูลจากชีทก็เชื่อทั้งก้อนไม่ได้
นิวเอาสารอาหารคูณกลับ **P×4 + C×4 + F×9** เทียบ kcal → เจอ **12 แถวเป็นไปไม่ได้ทางกายภาพ** (kcal 48 แต่รวมได้ 2,443) · ฝั่ง D ทั้งหมด · ช่องไขมันเป็นเลข 3 หลัก = คอลัมน์เลื่อน
→ **สูตรคูณกลับ = ด่านตรวจโภชนาการที่ถูกที่สุดที่มี ใช้ทุกครั้งที่ import จากที่อื่น** · และ **ไม่เดาค่าที่ถูก** ส่งกลับเจ้าของชีท

### ⚠️ บางข้อไม่ได้เพิ่งเกิด — แค่เพิ่งมีคนเปิดดู
· **แพคกับข้าวมีข้าวในรูป** มีมาก่อนแล้ว — โบรชัวร์ 7 ก.ย. รูป D3 มีข้าวไรซ์เบอร์รี่ และ D1/D3/D4/D5 ใช้รูปหน้าตาเดียวกับคู่ S
· **รูปครอปจากโบรชัวร์เก่ามีราคาฝัง** เป็นมาตั้งแต่ดูดรูปเข้าคลัง (u0.4.36)
· ที่เห็นรอบนี้เพราะ **กฎใหม่ 9 ก.ย. "ภาพต้องผ่านตานัท"** ทำให้มีคนเปิดดูภาพจริงเป็นครั้งแรก

### ✅ แก้ที่ต้นเหตุ
1. **ด่านตรวจข้อ ④** — โชว์ชื่อคู่ S/D ทุกคู่ให้คนเห็น + ธงเมื่อวิธีทำไม่ตรง (ต้ม/ผัด/ทอด…) + ธงเมื่อ D ใช้ไฟล์รูปเลขอื่น (ทดสอบกับชุดจริงแล้ว จับได้ทั้ง S145/D145 และไฟล์ยืม 3 ใบ)
2. **ด่านตรวจปิดท้าย** — เลิกขึ้น "ผ่านครบ ยิงได้" เปลี่ยนเป็น "ผ่านด่านเครื่อง แต่ยังยิงไม่ได้จนกว่าจะมีคนเปิดดูภาพ" (ข้อความเดิมคือความมั่นใจปลอม)
3. **กฎคู่ S/D** — ดูฉบับที่นิวปรับด้านบน (รอนัทเคาะ) · ส่วน "ถ้าคู่ไม่พอให้เปิด D น้อยลง" นิวยกเป็นคำถามแยกให้นัทตัดสิน เพราะนัทเคยสั่ง D1–D5
4. **สคริปต์ของ 05 ขึ้น main แล้ว** — ก่อนหน้านี้ทั้งด่านตรวจ/ตัวเฝ้าโควตา/สคริปต์ยิง อยู่ในเครื่องนี้เครื่องเดียว ไม่มีห้องไหนตรวจได้
