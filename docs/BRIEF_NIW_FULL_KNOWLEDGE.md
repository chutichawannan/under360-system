# ส่วนที่ 1 — วิธีทำงานกับนัท (สำคัญกว่าความรู้เทคนิค)

## 1.1 🔴 ของที่มีเส้นตาย = ลงก่อน ให้แก้ทีหลังได้
**เหตุการณ์จริง 15-16 ส.ค.:** ผมเสนอเมนูสัปดาห์หน้าให้นัท → นัทถามเรื่องรูปกับเมนู D → ผมไปตอบเรื่องนั้น แล้วต่อด้วย birthday promo · migrate รูป Hato · เขียนสคริปต์ — **โดยไม่ได้ลงเมนูให้จบ** ทั้งที่พรุ่งนี้ขึ้นสัปดาห์ใหม่แล้ว

นัทพูดกลับมาว่า:
> *"เรื่องทั้งหมดที่พูดมาแทบจะเป็นโกหกทั้งเพ **หยุดทุกขั้นตอน หยุดทุกอย่างอื่น** ยกเว้นเมนูพิเศษประจำสัปดาห์หน้าที่นายทำไม่สำเร็จ"*

**กฎ:** งานที่มีเส้นตายจริงในวันนั้น **ต้องเสร็จก่อนแตะอย่างอื่น** · ถ้าติดรายการเดียว **ลงไปก่อนแล้วให้นัทแก้ทีหลัง 10 วินาที** ห้ามบล็อกทั้งก้อน

## 1.2 🔴 ก่อนถามนัท — ไล่ย้อนก่อนว่านัทตอบไปแล้วหรือยัง
**เหตุการณ์จริง:** นัทบอกชัดว่า *"ในส่วน D5 ใช้ชื่อว่ามีทบอลอกไก่ d029"* → **ผมกลับเอา D029 ไปเป็น D4 แล้วหยิบ D152 มาเป็น D5 เอง แล้วยังถามซ้ำอีกว่า "เคาะ D5 ไหม"**

นัทตอบ:
> *"ในส่วน D5 ฉันก็บอกไปแล้วนี่นา"*

**กฎ:** นัททำงานหลายเรื่องพร้อมกัน ตอบสั้นและกระจาย — **หน้าที่เราคือจำและเอาไปใช้ ไม่ใช่ให้นัทพูดซ้ำ**

## 1.3 🔴 "ใช้ของที่มีใน DB ก่อน" — สร้างใหม่ต่อเมื่อไม่มีจริงๆ
> นัท: *"อย่าบอกนะว่านายสั่งสินค้าใหม่ทั้งหมด ไม่ได้เอาข้อมูลใน DB มาใช้ **จะสร้างใหม่ก็ต่อเมื่อมันไม่มีสินค้าจริงๆ นะ**"*

ร้านมีเมนูใน DB **611 รายการ** — ของที่ต้องใช้เกือบทั้งหมด**มีอยู่แล้ว**
**ก่อนสร้างเมนูใหม่ ต้องพิสูจน์ให้ได้ว่าไม่มีจริง 3 ชั้น:** ค้นด้วย**รหัส** → ค้นด้วย**ชื่อ/คำสำคัญ** → เทียบ **แคตตาล็อก Hato** (`kitchen_data.hato_catalog_dump` 638 รายการ)

## 1.4 🔴 แก้ที่ข้อมูล ห้ามแก้ที่โค้ดหน้าจอ (ช่วงเบต้า)
> นัท: *"ขอความกรุณาไม่ปิดผ่าน coding ปิดผ่านระบบที่เป็นหน้า db เท่านั้น **เหตุผลเพราะว่าตอนนี้ระบบของเราเบต้าแล้ว ถ้าเราไปแก้ผ่าน coding จะยิ่งมีปัญหา เพราะเราทำงานร่วมกับ admin**"*

- ❌ **ห้าม**เพิ่มเงื่อนไขใน LIFF ให้ *ซ่อน* ของ → แอดมินเปิดหน้า DB จะเห็นว่า "เปิดขาย" = **ความจริง 2 ชุด** ทำงานกับแอดมินแล้วเถียงกันว่าใครถูก
- ✅ **ต้อง**แก้ที่ข้อมูล (`is_available` ฯลฯ) ให้หน้าหลังบ้านกับหน้าลูกค้า**ตรงกัน 100%** และแอดมินกดแก้เองได้
- เช่นเดียวกัน: **+฿40 อาหารทะเล ต้องอยู่ที่ `package_items.extra_price` ห้าม hardcode** — นัทบอก *"หน้านี้คือหน้าคนทำจริง ถ้านายไปออกโค้ดหลังบ้าน ต้องมาแก้กันอีก"*

## 1.5 🔴 "audit ผ่าน" ≠ "ลูกค้าเห็นถูก"
**เหตุการณ์จริง 8 ส.ค.:** ผม audit ผ่านหมด 5 ข้อฝั่ง DB แล้วรายงานว่าเรียบร้อย → **นัทเปิด LIFF จริงเจอบั๊กทันที 4 ข้อ** (เรียงมั่ว · ไม่มีแท็ก · ไม่จัดกลุ่ม · แคลรกจอ)

**กฎ:** ตรวจชั้นข้อมูลไม่พอ **ต้องมีคนเปิดหน้าจอจริงเสมอ** · ถ้าเปิดเองไม่ได้ (LIFF ต้อง login LINE) → **บอกนัทตรงๆ ว่ายังไม่ได้ยืนยันด้วยตา** อย่าเขียนว่า "เรียบร้อย"

## 1.6 🔴 ห้ามรับปากสิ่งที่ทำไม่ได้ — ประเมินตัวเองก่อน
**เหตุการณ์จริง:** นัทขอให้แก้ภาพโบรชัวร์ ผมตอบ *"ทำได้แน่"* ทั้งที่ยังไม่รู้วิธี → ผลออกมาพังทุกจุด (รูปเก่าค้าง · ล้นกรอบ · ฟอนต์ไทยผิด · ข้อมูลบนล่างขัดกัน)

นัท:
> *"นายไม่ได้ประเมินตัวเองเลยว่านายทำไม่ได้ ... ต่อจากนี้ไม่ต้องทำภาพให้ฉัน"*

**กฎ:** **Claude ทำภาพกราฟิก/โบรชัวร์ไม่ได้** — ไม่มี image library · ไม่มีฟอนต์ไทย · วัดพิกัดไม่ได้
**แบ่งงานที่ถูก:** เรา = เลือกเมนู · เตรียมข้อมูล/CSV · เขียน copy | **นัท = พิกเซล/โบรชัวร์**

## 1.7 "เสร็จ" ต้องมีหลักฐานที่ query ซ้ำได้
ห้ามบอกว่าเสร็จจากความจำหรือจากเอกสาร — **ต้อง query จาก DB จริงแล้วนับแถวได้** · เอกสารเป็น snapshot เก่าเสมอ

## 1.8 วิธีเสนองาน
- **สั้น ตรงประเด็น ทีละเรื่องเดียว** — อย่ายัดหลายหัวข้อในเทิร์นเดียว
- **เสนอเป็นตัวเลือกให้เคาะ** พร้อมข้อเสนอแนะว่าควรเลือกอันไหน (นัทตัดสินใจเร็วขึ้นมาก)
- ซ่อนขั้นตอนระหว่างทาง เอาเฉพาะสิ่งที่นัทต้อง**เห็น/ตัดสินใจ**

# ส่วนที่ 2 — ความรู้เรื่องระบบเมนู

## 2.1 โครงสร้าง 2 ฝั่ง
| | |
|---|---|
| **`S###`** | ข้าวกล่อง (มีข้าว) · หมวด `no_special` · แท็บ LIFF **⭐ สัปดาห์นี้** |
| **`D###`** | แพคกับข้าว (ไม่มีข้าว) · หมวด `pack_regular` · แท็บ **📦 แพคกับข้าว** |
| `No#` / `A##` | เมนูประจำร้าน (ไม่หมุนรายสัปดาห์) |
| `HP##` / `LC##` | Meal Plan ทำสด (คนละระบบ · ส่ง จ/พ/ศ เท่านั้น) |

## 2.2 กลไก "เมนูพิเศษประจำสัปดาห์" — 4 ชั้น ต้องครบทุกชั้น
1. **`category`** → คุมว่าโผล่แท็บไหน **และ**เข้าเซ็ตไหน (Diet Set ดึงจาก `no_special` · Protein Pack ดึงจาก `pack_regular`) — **ตั้งผิด = ลูกค้าสั่งในเซ็ตไม่ได้**
2. **`is_available`** → เปิด/ปิดขาย
3. **`subcode`** → ชื่อเล่น S1-S8 / D1-D5 ที่**ครัวและลูกค้าเรียกกันจริง**
4. **`kitchen_data.menu_special_weeks`** → แท็กสัปดาห์ `{ "S022": "2026-08-10" }` (วันจันทร์ของรอบนั้น)

## 2.3 กติกาชื่อเล่น (นัทเคาะเอง)
> *"ชื่อเล่น S1 S2 มีได้แต่ชื่อเดียว ไม่งั้นเกิดความสับสน **มีเมนูใหม่เข้ามา เมนูเก่าต้องลบชื่อเล่นออก** ไม่ต้องใส่ S ให้เหลือแค่ชื่อจริง code พอ"*

- **1 ชื่อเล่น = 1 เมนู เท่านั้น**
- เมนูรอบเก่าที่ยังขายอยู่ → **ลบชื่อเล่น แต่คงแท็กสัปดาห์ไว้** (ลูกค้าจะได้รู้ว่าเป็นของรอบไหน)
- ⛔ **เลิกใช้ระบบเติม `x` นำหน้า (`xs3`) แล้ว** — ใช้วันที่แทน · ถ้าเจอ `xs`/`xd` แปลว่ามีคนใส่ผิดกติกา

## 2.4 🔴 S กับ D — จับคู่ด้วย **ชื่อ** ห้ามใช้รหัส
เคยเชื่อกันว่า *"เลขตรงกัน = เมนูเดียวกัน"* → **ตรวจทั้งร้านแล้วไม่จริง**

| | |
|---|---|
| คู่ที่เลขตรงกัน | **93 คู่** |
| **ผิด (คนละเมนู)** | **46 คู่ ≈ ครึ่งหนึ่ง** |
| รหัส **< 100** ผิด | 11% |
| รหัส **≥ 100** ผิด | **83%** ← กติกาถูกเลิกใช้ไปเองตั้งแต่ยุคนี้ |

ตัวอย่างที่พังจริง: `S157 ผักกาดห่ออกไก่` ↔ `D157 กุ้งผัดต้มยำแห้ง` · `S063 ไก่ย่างพริกสามรส` ↔ `D063 อกไก่ผัดเปรี้ยวหวาน`

**🚨 ผลกระทบ: ไก่↔กุ้ง 5 คู่ · ไก่↔ปลา 4 คู่ → จับคู่/ยืมรูปด้วยเลข = ผิดชนิดโปรตีน = เสี่ยงเรื่องของแพ้**
**ไม่ใช่บั๊กตอน migrate** — 39/44 ชื่อตรงกับ Hato เป๊ะ = ต้นทางผิดมาก่อน
📄 รายละเอียด: `docs/AUDIT_SD_CODE_MISMATCH.md` · ⏳ **รอนัทเคาะว่าจะแก้แบบ A (ย้ายรหัส) หรือ B (บันทึกคู่ไว้)**

## 2.5 🔴 ไม่มีสูตร/วัตถุดิบในระบบเลย
`recipes` · `ingredients` · `menu_ingredients` · `materials` · `inventory` = **404 ทั้งหมด** · `menu_items` ไม่มีคอลัมน์สูตร
หน้า DB แตะแค่ 7 ตาราง ไม่มีตารางวัตถุดิบสักตัว

**→ ถ้านัทขอ "วัตถุดิบตามสูตร" ตอบให้ไม่ได้จริงๆ** ต้องบอกตรงๆ แล้วเสนอทางเลือก (ประเมินจากชื่อเมนู + **ติดป้ายว่าเป็นการประเมิน**)
**ราคา/แคล ก็ไม่ครบ** — ต้องเทียบกับโบรชัวร์ที่นัททำเสมอ (เคยเจอ `S063` ใน DB ฿110 แต่โบรชัวร์ ฿125)

## 2.6 เรื่องรูป
- Storage เรา = **800×800** (ดูดจากโบรชัวร์เก่า) · **นัทบอกเองว่าไม่ชัดพอทำโบรชัวร์ใหม่**
- **Hato มีต้นฉบับ 1024×1024 ครบ 630/638** — สุ่มเทียบ 30 ตัว: Hato ชนะ 28 · เสมอ 2 · **เราชนะ 0**
- แคตตาล็อก Hato ดึงเก็บไว้แล้ว: `kitchen_data.hato_catalog_dump` (`{sku, n, a, img, cnt}`)
  ⚠️ `img` เป็น template — ต้องแทน `{width}x{height}` → `1024x1024` ไม่งั้น HTTP 502
- 🔴 **migrate รูปยังไม่ได้ทำ** · ถ้าทำ **ต้องจับคู่ด้วยชื่อ ไม่ใช่เลข** (ดู 2.4)

**สิ่งที่นัทต้องการจากเราทุกสัปดาห์:** เมนูแต่ละตัว**เคยลง week ไหน ช่อง S ที่เท่าไหร่** + **จัดกลุ่มตาม week** → นัทเปิดคลังรูปเดิมดึงต้นฉบับเอง (เปิดโฟลเดอร์น้อยที่สุด)

## 2.7 ของที่เหลือ = เงินที่กำลังจะกลายเป็นของทิ้ง
- เมนูรอบเก่าที่ยังขายอยู่มี **~19 ตัว** บางตัวเหลือ 1-3 บางตัวไม่จำกัด
- นิวเฝ้าได้แล้ว: สัปดาห์ 10-16 เตือน **"เสี่ยงเหลือ" 10 เมนู ~46 กล่อง** (กุ้งผัดซอสอบวุ้นเส้น **ผลิต 9 ขาย 1**)
- **หางยาว:** วันที่ 17 ส.ค. มี **30 เมนูที่สั่งแค่ 1 กล่อง** → เปิดวัตถุดิบเต็มแพ็คเพื่อทำ 1 กล่อง
- 💡 **ส่งลิสต์ "เสี่ยงเหลือ" ให้ห้อง 05 ตั้งแต่กลางสัปดาห์** → ยิงโปรดันขาย**ก่อนมันเหลือ** ดีกว่าลดราคาตอนค้างแล้ว

# ส่วนที่ 3 — กับดักเทคนิค (โดนมาแล้วทุกอัน)

## 🧨 แพทเทิร์นใหญ่: **เครื่องมือคืนผลลวงโดยไม่มีอะไรแดง**
| กับดัก | อาการ | ทางแก้ |
|---|---|---|
| **`stock_total = null` = "ไม่จำกัด" ไม่ใช่ "หมด"** | เช็ค `!stock_total` → ปิดเมนูไม่จำกัดทิ้งยกแผง | แยก `null` / `0` / `N>0` |
| **PATCH/DELETE คืน `204 สำเร็จ` ทั้งที่ไม่มีแถวถูกแตะ** | เขียนแล้วนึกว่าเสร็จ แต่ข้อมูลไม่ขยับ | **query กลับมานับทุกครั้ง** |
| **ลบ `orders` ผ่าน anon ไม่ได้** | DELETE 204 แต่แถวยังอยู่ → **ใบเทสค้าง ครัวทำอาหารทิ้ง** | `PATCH status='cancelled', total=0` · ⚠️ `delivery_date=null` ไม่ได้ (NOT NULL → 400 ทั้งก้อน) |
| **`.select()` ไม่มี `.limit()` → คืนแค่ 1,000 แถว** | นับยอดขาดเงียบๆ | paginate `.range()` เสมอ |
| **curl + ข้อความไทยบน Windows** | ได้ `???` / HTTP 400 | เขียน JSON ลงไฟล์ → `--data-binary @file` |
| **`node` ไม่อยู่ใน PATH** | command not found | `"C:/Program Files/nodejs/node.exe"` |
| **`node -e` กับข้อความไทย+backtick** | shell กินทิ้ง ข้อความหายเป็นช่วง | เขียนเป็นไฟล์ `.mjs` แล้วรัน |

## 🌳 กฎ git
- **ห้าม `git checkout <branch>` ในทรีหลัก** — หลาย session ใช้ร่วมกัน งานที่ยังไม่ commit **ถูกล้างหายจริงมาแล้ว 2 รอบ** → ใช้ `git worktree`
- **commit ทันทีที่เสร็จ ไม่รอจบ session**
- 🔴 **"แก้เสร็จ" ≠ "ถึงลูกค้า"** — เคยมีของแก้เสร็จค้างบน branch **8 วัน** จนนัทเจอบั๊กเดิมเองอีกรอบ
  → **มี Stop hook `scripts/cc_stop_check.mjs` จับให้แล้ว** (branch ค้าง >2 วัน · ใบเทสค้าง · เมนูสัปดาห์หน้ายังไม่ลง)

## 🔒 กติกาหลายห้อง
- **จองใน `work_claims` ก่อนลงมือ** · เจอคนจองแล้ว = ไม่ทำ ให้ถามเจ้าของ
- ถ้านัทสั่งตรงแล้วทับ claim ห้องอื่น → **ทำได้ แต่ต้องแจ้งห้องนั้นทันที** ไม่ให้ทำซ้ำ
- **บอร์ด = ตู้ไปรษณีย์ ไม่ใช่กระดิ่ง** — ส่งแล้วห้องนั้นไม่รู้ ต้องปลุก
