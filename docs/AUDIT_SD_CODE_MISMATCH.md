## หมายเหตุรายตัว

- **136** — ชื่อ S136 ใน Hato = "ข้าวยำไข่มะตูมอกไก่สับ" (ในระบบเราเป็นโกยซีหมี่) — ผิดคู่ทั้งสองระบบ
- **137** — ⚠️ **ที่ Hato คู่นี้ถูกต้อง** (S137 = บะหมี่ผักหมูสับต้มยำขลุกขลิก ↔ D137 = หมูสับต้มยำขลุกขลิก) — ชื่อ S137 ในระบบเราถูกเปลี่ยนเป็น "บะหมี่ผักคลุกซอสหมูแดงเห็ดหอมผัด" ทีหลัง = **เพี้ยนที่ระบบเรา ไม่ใช่ Hato**
- **149** — ต่างกันแค่คำว่า "เห็ดหอม" ที่ท้ายชื่อ S — ผิดคู่ทั้งสองระบบ
- **159** — ชื่อ S159 ใน Hato = "ข้าวน้ำพริกอกไก่ ไข่ต้ม" — ผิดคู่ทั้งสองระบบ
- **201** — Hato ไม่มี D201 เลย = D201 ถูกสร้างในระบบเรา · แถมชื่อซ้ำกับ S063 (ไก่ย่างราดพริกสามรส)

## แพทเทิร์นความผิดพลาด

1. **ผิดเกือบทั้งหมดอยู่ที่รหัส 100 ขึ้นไป**
   - รหัส < 100: 46 คู่ → ผิด **5 คู่ (11%)**
   - รหัส ≥ 100: 47 คู่ → ผิด **39 คู่ (83%)**
   - ช่วง 100–201 คือ **แทบทุกคู่ผิดหมด** — ตีความได้ว่า **กติกา "เลขเดียวกัน = เมนูเดียวกัน" ถูกใช้แค่ช่วงรหัสแรกๆ แล้วเลิกใช้ไปเอง** พอถึงยุคหลังก็แจกเลข S และ D แยกกันคนละคิว
2. **ผิดมาจาก Hato ตั้งแต่แรก ไม่ใช่เพี้ยนตอน migrate** — 39 จาก 44 คู่ที่ผิด ชื่อทั้งสองฝั่งตรงกับ Hato เป๊ะ (ต่างแค่คำนำหน้าแบบ `XS2`/`XXD4` ซึ่งเป็นชื่อเล่นเมนูพิเศษ) → **ระบบเราลอกมาถูก แต่ต้นทางผิดอยู่แล้ว**
3. **มี 1 คู่ที่เพี้ยนในระบบเราเอง = S137** (ที่ Hato คู่นี้ตรงกัน) และ **1 รายการที่สร้างใหม่ = D201** (Hato ไม่มี)
4. **ไม่ใช่แค่คนละเมนู — บางคู่คนละโปรตีนเลย** (ไก่↔กุ้ง `108/144/153/157/162` · ไก่↔ปลา `136/142/150/154` · ไก่↔หมู `037/101/134/165`) → **ถ้าใครใช้รหัสอ้างอิงข้ามฝั่ง S/D จะได้ของแพ้/ผิดชนิดโปรตีน** อันตรายกว่าแค่ชื่อผิด
