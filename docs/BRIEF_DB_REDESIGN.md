# บรีฟ: รื้อดีไซน์หน้าฐานข้อมูล (`main_database_v2.html`)

> นัทสั่งเอง 14 ก.ย. 2569: *"ฉันอยากเปลี่ยน design มาก มันไม่น่าใช้งานเลย"*
> และ *"หากันในระดับที่ไม่รัดตัวดีไซเนอร์เกินไป"*
>
> **ใบนี้บอกแค่ว่าอะไรพังไม่ได้ — ไม่ได้สั่งว่าต้องสวยยังไง**
> สี ฟอนต์ เลย์เอาต์ ระยะห่าง จัดกลุ่มใหม่ ยุบ/แยกแท็บ — **คิดได้เต็มที่ ไม่มีข้อห้าม**

---

## 1. หน้านี้มีไว้ตอบคำถามอะไร

คนใช้คือ **นัท (เจ้าของ/หัวหน้าครัว) กับแอดมิน** — เปิดหน้านี้เพื่อตอบ 5 คำถาม:

1. **เมนูนี้ทำยังไง** — สูตร วัตถุดิบ ปริมาณ ต้นทุน
2. **ตอนนี้มีของเท่าไหร่ ขายได้อีกกี่ชิ้น**
3. **อาทิตย์นี้ขายอะไรบ้าง** — เปิด/ปิดเมนู ตั้งราคา ตั้งชื่อเล่น (s1–s8)
4. **แพค/เซ็ตมีอะไรอยู่ข้างใน ราคาเท่าไหร่**
5. **ใครแก้อะไรไปเมื่อไหร่** — ประวัติการเปลี่ยนแปลง

จุดเจ็บที่นัทบอก: **"ไม่น่าใช้งาน"** — หน้าแน่น ของเยอะ ไม่รู้จะเริ่มตรงไหน
(ไม่ได้บอกว่าอะไรใช้ไม่ได้ — ของใช้ได้หมด แค่ใช้แล้วเหนื่อย)

## 2. ในหน้ามีอะไรบ้าง (ภาษาคน)

| แท็บ | ทำอะไร |
|---|---|
| **เมนูทั้งหมด** | ตัวหลัก — รายการเมนูทุกตัว เปิด/ปิดขาย ราคา รูป สูตร ชื่อเล่น จัดหมวด ลากเรียงลำดับ |
| **วัตถุดิบ** | คลังวัตถุดิบ ราคาต่อหน่วย ใช้คิดต้นทุนเมนู |
| **แพลนซื้อวัตถุดิบ** | รวมว่าต้องซื้ออะไรเท่าไหร่ |
| **📅 Meal Plan** | 2 หน้าย่อยคนละเรื่อง: **แผนผลิต** (กริดวางแผนหลายวัน) กับ **ผลิตวันนี้** (ครัวดูว่าวันนี้ต้องทำอะไร) |
| **📦 แพคเกจ** | สร้างแพค/เซ็ต/คอร์ส — เลือกเมนูเข้าเซ็ต ตั้งราคาเหมา แบ่งรอบส่ง |
| **🏷️ บ่อเซล** | ลดราคาเมนูเฉพาะตัว |

**นอกแท็บ** — แถบบนสุด: ค้นหา · แถบหมวดหมู่ (ลากเลื่อนได้) · **แถบประวัติการแก้ไข (Activity Log)** · ชื่อคนที่กำลังใช้งาน

## 3. 🔴 อะไรห้ามแตะ (ผิดข้อเดียว = ของจริงพัง ลูกค้าสั่งอาหารไม่ได้ / ครัวทำผิด)

**หน้านี้ไม่ใช่หน้าจอเปล่า — ทุกปุ่มเขียนลงฐานข้อมูลจริงทันทีที่คลิก ไม่มีปุ่ม "บันทึก" รวม**

### ก. โครงไฟล์
- **ไฟล์เดียวจบ** — HTML + CSS + JS อยู่ในไฟล์เดียว **ห้ามแยกเป็น .css / .js**
  (ทั้งระบบใช้กติกานี้หมด แยกแล้ว deploy ไม่ขึ้น)
- ต่อฐานข้อมูลผ่าน `getSB()` เท่านั้น — `const sb = getSB();` **ห้ามสร้าง client เอง**

### ข. ชื่อที่ห้ามเปลี่ยน (ผูกกับฐานข้อมูลจริง)
- ตารางที่หน้านี้เขียนจริง: `menu_items` · `packages` · `package_items` · `mp_offer_sets` · `kitchen_data` · `activity_log` · `mp_deliveries` · `home_layout`
- **`stock_total` คือคอลัมน์สต็อกตัวจริง** — ไม่มีคอลัมน์ชื่อ `stock_quantity` อยู่ในระบบ
  (เคยเข้าใจผิดมาก่อน แล้วสต็อกพังทั้งเส้นทาง)
- ความหมายของ `stock_total`: **ว่าง = ไม่จำกัด · 0 = หมดจริง · N = เหลือ N**
  สามค่านี้ต้องแยกกันออกด้วยตาบนหน้าจอ — "ว่าง" กับ "0" **ไม่เหมือนกัน**
- `subcode` = ชื่อเล่นเมนู (s1–s8) ที่ครัว**และลูกค้า**ใช้เรียก · ค้างข้ามสัปดาห์เติม `x` นำหน้า
- ปุ่ม **"ขึ้นสัปดาห์ใหม่"** เปลี่ยนชื่อเล่นทั้งชุดรวดเดียว — ปุ่มเดียวกระทบทุกเมนู

### ค. พฤติกรรมที่ต้องเหลืออยู่
- **ลากเรียงลำดับได้** ทั้งลำดับเมนูและลำดับหมวด (ลำดับนี้คือลำดับที่ลูกค้าเห็นจริง)
- **แถบหมวดหมู่ลากเลื่อนซ้าย-ขวาด้วยเมาส์ได้**
- **Activity Log** ต้องยังเห็นได้จากหน้าหลัก (ใครแก้อะไร = เรื่องความรับผิดชอบ ไม่ใช่ของประดับ)
- ทุกช่องที่กรอกแล้วมีผลทันที ต้อง**เห็นได้ชัดว่ามันมีผลทันที**

## 4. ข้อจำกัดที่รู้อยู่แล้ว (ไม่ใช่บั๊กให้แก้ แต่ห้ามทำให้แย่ลง)

- **ดึงข้อมูลได้ทีละ 1,000 แถว** — ถ้าทำหน้าใหม่ที่ดึงออเดอร์/ลูกค้า ต้องแบ่งหน้าเอง
  ไม่งั้นได้ข้อมูลไม่ครบ **แบบเงียบ ๆ ไม่มี error**
- ไฟล์ใหญ่ **~495 KB / 6,054 บรรทัด** — เปิดบนมือถือช้าอยู่แล้ว **อย่าทำให้หนักกว่าเดิม**
  (เคยลดจาก 778 KB มาแล้วครั้งหนึ่ง)
- **เมนู HP/LC ไม่ต้องขึ้นให้ลูกค้าเลือก** — มีไว้ให้แอดมินจ่ายหลังบ้านเท่านั้น (ตั้งใจ ไม่ใช่บั๊ก)
- หน้านี้ใช้บนทั้งคอมและมือถือ — ครัวเปิดบนมือถือจริง

## 5. สิ่งที่อยากได้จริง ๆ จากรอบนี้

> **"เปิดมาแล้วรู้ว่าจะเริ่มตรงไหน"**

ไม่ต้องรักษาหน้าตาเดิมไว้เลย · จะยุบแท็บ รวมของ ซ่อนของที่ใช้น้อย ทำใหม่หมดก็ได้
ขอแค่ **ของทุกอย่างในข้อ 3 ยังทำงานเหมือนเดิม** และ **ไม่มีเลขไหนบนหน้าจอที่โกหกคนอ่าน**

## 6. ส่งกลับมายังไง

ส่งเป็น **ไฟล์ `.html` ไฟล์เดียว** กลับมา → ห้อง u จะ:
1. เทียบว่าฟังก์ชันที่ต่อฐานข้อมูลยังครบ
2. เปิดดูด้วยตาบนคอม + มือถือ
3. ขึ้นของจริงให้

**ห้ามขึ้นเองโดยไม่ผ่านห้อง u** — หน้านี้ครัวกับแอดมินใช้ทำงานอยู่ทุกวัน
