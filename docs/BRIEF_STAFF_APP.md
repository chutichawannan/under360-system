## 1. โจทย์ที่เจ้าของร้านวางไว้ (คำของเขาเอง 23 ก.ย. 2569)

> *"พอล็อกอิน Google แล้วจะได้รู้ว่าคนคนนี้มีสิทธิ์เป็นครัว หรือแอดมิน หรือเจ้าของ (เมลที่เคยลงทะเบียนไว้แล้ว)
> หลังจากนั้น**หน้าดีฟอลต์จะเป็นหน้าของคนคนนั้นไปเลย** โดยที่หน้าแต่ละหน้าก็สามารถข้ามไปหาห้องอื่นได้
> เช่นหน้าของครัวก็ยังมีปุ่มห้องนัทหรือปุ่มห้องแอดมินให้กดอยู่ แต่หน้า default ของเขาก็จะเป็นของครัวไปหมด
> ซึ่งก็จะคล้าย ๆ กับหน้า command center เลย ... **จะได้ยุบ command center ทิ้งในอนาคต**
> เพราะเรา develop หน้าแอพให้ใช้งานหลังบ้านได้เลย โดยมี **staff subdomain คลุมทุกอย่าง**"*

**เป้าหมายที่แท้จริง:** ทุกวันนี้ทีมต้องจำว่าเครื่องมือแต่ละอย่างอยู่ลิงก์ไหน (มี 30+ หน้า)
→ ทำให้ **"เปิดแอปแล้วเจอของที่ตัวเองต้องใช้"** โดยไม่ต้องเรียนรู้อะไรเลย

```

staff/auth.js        134 บรรทัด   🔑 ล็อกอิน Google + รายชื่ออีเมลที่อนุญาต  ← ส่วนนี้ใช้ได้จริงแล้ว
```

**เส้นทางที่ชี้มาที่นี่แล้ว:** `/` · `/staff` · `/staff/v2` · `/staff/v2/home` · `/staff/v2/nut`

### สิ่งที่ยังไม่มี (= งานหลักของคุณ)
1. **หน้าเริ่มต้นตามสิทธิ์** — ตอนนี้ทุกคนเห็นหน้าเดียวกันหมด ยังไม่ได้แยกครัว/แอดมิน/เจ้าของ
2. **ห้องครัว กับ ห้องแอดมิน ในแอป** — ตอนนี้การ์ดกดแล้วเด้งออกไปหน้าเก่านอกแอป (`/k`, `/oh`)
3. **ปุ่มข้ามห้อง** ที่เจ้าของพูดถึง
4. **ของที่ยกมาจาก command center** (ดูข้อ 4)

## 3. ล็อกอินทำงานยังไงตอนนี้ (`staff/auth.js` — ส่วนนี้แนะนำให้ใช้ต่อ)

```
1. ผู้ใช้กด "เข้าสู่ระบบด้วย Google" → Supabase Auth (provider google)
2. กลับมาพร้อม access_token ท้าย URL → ยิงถาม /auth/v1/user ว่าอีเมลอะไร
3. อีเมลอยู่ในรายชื่อที่อนุญาตไหม  ไม่อยู่ = ขึ้น "อีเมลนี้ยังไม่ได้รับอนุญาต"
4. จำไว้ใน localStorage 60 วัน + ต่ออายุทุกครั้งที่เปิดหน้า   (แก้บั๊ก 23 ก.ย. เดิมหลุดทุก 1 ชม.)
5. เปิดตัวแปรให้ทุกหน้าใช้ต่อ:  window.U360_EMAIL  ·  window.U360_ROLE ('owner' | 'employee')
6. เข้า Google ไม่ได้ → ถอยไปรหัส 4 ตัว (ครัวใช้ทางนี้)
```

**รายชื่อสิทธิ์อยู่ในไฟล์นี้ตรง ๆ** (ตัวแปร `OWNERS` และรายชื่อที่อนุญาต)
🟡 ตอนนี้แยกได้แค่ 2 ระดับ (เจ้าของ / พนักงาน) — **โจทย์ของคุณคือ 3 ระดับ (ครัว/แอดมิน/เจ้าของ)** จะขยายในไฟล์นี้ หรือย้ายรายชื่อไปเก็บใน `kitchen_data` เพื่อให้เจ้าของแก้เองได้ ก็แล้วแต่คุณ

⚠️ **ข้อเท็จจริงเรื่องครัว:** ครัว 6 คนเป็นชาวไทใหญ่ ใช้เครื่องร่วมกัน ไม่ได้มีบัญชี Google ทุกคน
เจ้าของบอกว่า**เรื่องล็อกอินของครัวเขาจัดการเอง** — ออกแบบเผื่อไว้ว่าฝั่งครัวอาจเข้าด้วยรหัสสั้น ไม่ใช่ Google

## 4. command center — ของที่ต้องยกมาก่อนถึงจะยุบได้

`command_center.html` (1,420 บรรทัด) ไม่ใช่แค่หน้ารวมลิงก์ — มันคือ **ที่ที่ห้องทำงานทั้งหมดคุยกัน**
ถ้ายุบก่อนยกของ ห้องทั้งระบบจะตาบอดพร้อมกัน

| สิ่งที่มันทำ | ข้อมูลจาก | ใช้จริงแค่ไหน |
|---|---|---|
| **กล่องจดหมายระหว่างห้อง** | ตาราง `session_messages` (room · sender · text · created_at) | **390 ฉบับใน 7 วัน · 26 ห้อง** — ใช้หนักมาก |
| **สถานะห้อง/เวอร์ชัน** | ตาราง `track_status` (room · status · current · version · open_loops) | ใช้ดูว่าห้องไหนเดินถึงไหน |
| **จองงานกันชนกัน** | ตาราง `work_claims` | ใช้กันสองห้องแก้ไฟล์เดียวกัน |
| ยอดขายรายเดือน · วันนี้ต้องทำ · ลิงก์ทุกหน้า | `orders` · `menu_items` · `kitchen_data` | ซ้ำกับห้องนัทในแอปบางส่วน |

**ห้องที่ส่งจดหมายบ่อยสุด 7 วันล่าสุด:** 06(48) · 05(40) · pm(36) · เลขา(32) · u(27) · นิว(24) · f(18) · m(17) · kapan(16)

**เงื่อนไขการยุบ (เจ้าของเห็นด้วยแล้ว): ยกกล่องจดหมาย + สถานะห้อง เข้าแอปก่อน แล้วค่อยยุบ**
🟢 จะออกแบบให้กล่องจดหมายหน้าตาเป็นยังไงในแอป = เรื่องของคุณ (ตารางเดิมใช้ต่อได้เลย ไม่ต้องย้ายข้อมูล)
