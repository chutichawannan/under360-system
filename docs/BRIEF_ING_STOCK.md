## 3. ข้อมูลที่ต่อได้ทันที (ของจริง นับแล้ว ณ 23 ก.ย. 2569)

### 3.1 `kitchen_data` — ตารางเก็บของจิปาถะ โครงสร้าง `{ key, data(jsonb), updated_at }`
**anon เขียนได้เลย ไม่ต้องรัน SQL** — ทางที่เร็วที่สุดถ้าอยากเริ่มวันนี้

| key | เนื้อใน |
|---|---|
| `ingredients` | **array 302 ตัว = วัตถุดิบหลักของร้าน** (หน้า DB แท็บวัตถุดิบใช้อยู่) |
| `recipes` | **array 926 สูตร** · 844 สูตรมีบรรทัดวัตถุดิบจริง |
| `f_go_catalog` · `f_freshket_catalog` · `supplier_orders_*` | ของจากใบสั่งซื้อจริง (ห้องการเงินดูแล) |
| `ing_*` | **เขตของคุณ — ตั้งคีย์ใหม่ได้เลย** |

**1 แถวใน `ingredients` หน้าตาจริง:**
```json
{ "id":"i1781925201806tyg3", "name":"กระเทียม", "type":"ingredient", "unit":"g",
  "stock":0, "ingCategory":"เครื่องเทศ", "ingEmoji":"🧄",
  "suppliers":["market"], "defaultSupplier":"market", "market_price_kg":0,
  "cost_per_unit":0, "kcal_per_unit":1.49, "protein_per_unit":0.064,
  "carb_per_unit":0.331, "fat_per_unit":0.005 }
```

**1 สูตรใน `recipes` (เฉพาะส่วนที่เกี่ยวกับวัตถุดิบ):**
```json
{ "id":"r1786281810626", "name":"LC84 Sushi Bake แซลมอน ปูอัด", "code":"", "status":"active",
  "parts":[ { "label":"", "instructions":"", "lines":[
      { "qty":"400", "name":"สะโพกไก่", "unit":"g" },
      { "qty":"",    "name":"เกลือ",     "unit":"g" } ] } ] }
```

🔴 **จุดสำคัญที่สุดของการเชื่อม: บรรทัดในสูตรอ้างวัตถุดิบด้วย "ชื่อ" (string) ไม่ใช่ id**
→ ถ้าจะคำนวณ "ผลิตเมนูนี้ N กล่อง ใช้วัตถุดิบอะไรเท่าไหร่" ต้องแม็พด้วยชื่อ
→ และ `qty` เป็น **string** บางบรรทัดว่าง (เช่น "เกลือ") = ต้องเผื่อค่าว่างเสมอ
→ ของที่ทำเสร็จแล้วของคุณ ถ้ามี dictionary ชื่อวัตถุดิบอยู่แล้ว **ให้แม็พเข้ากับชื่อในชุดนี้** อย่าตั้งชุดใหม่ทับ
  (สูตร 844 สูตร + ราคา + ใบสั่งซื้อ ผูกกับชื่อชุดนี้หมดแล้ว · เจ้าของไล่ยืนยันเองทีละชื่อเมื่อ 16 ก.ย.)

### 3.2 ตาราง `ingredient_prices` (72 แถว · ห้องการเงินดูแล · อ่านได้ ห้ามเขียนทับ)
```
id · name · vendor(go|freshket) · vendor_sku · vendor_name · grade
pack_size · pack_unit · pack_size_kg · price · price_per_kg · in_stock · checked_at · note
```
ใช้ตอบว่า "ของชิ้นนี้ซื้อที่ไหนถูกกว่า / ต้องจ่ายกี่บาท"

### 3.3 ตารางอื่นที่อ่านแล้วมีประโยชน์กับการคำนวณยอดสั่ง
| ตาราง | ใช้ทำอะไร |
|---|---|
| `menu_items` | เมนูที่ขายอยู่ (`is_available`) · สต็อกเมนู (`stock_total` = ขายได้อีก, `actual_stock` = ในตู้) |
| `orders` + `order_items` | ดีมานด์จริงย้อนหลัง/ล่วงหน้า (`delivery_date`, `menu_code`, `quantity`, `status`) |
| `activity_log` | ประวัติการนับสต็อกเมนูของครัว — ใช้ดูจังหวะการผลิตจริง |

### 3.4 `activity_log` — ที่จดว่า "ใครทำอะไร" (แนะนำให้จดทุกครั้งที่เขียนข้อมูล)
```
{ session_id, actor, source:'ing', action_type:'stock',
  summary:'ข้อความสั้นที่คนอ่านรู้เรื่อง', detail:{ ...อะไรก็ได้ } }
```
หน้าประวัติที่มีอยู่แล้วอ่านตารางนี้ = ของคุณจะโผล่ในประวัติเองโดยไม่ต้องทำหน้าใหม่

## 4. ถ้าจะสร้าง "ตารางใหม่" (ไม่ใช้ kitchen_data)

anon key **เขียนตารางที่ยังไม่มี RLS policy ไม่ได้** — เงียบ ไม่ error ให้เห็นด้วย
ทำตามนี้: เขียน SQL แล้วส่งมาที่ห้อง u → u ตรวจ → **เจ้าของร้านเป็นคนรันเองใน Supabase SQL editor**

```sql
create table if not exists ing_counts (
  id          uuid primary key default gen_random_uuid(),
  item_key    text not null,              -- ผูกกับชื่อ/id วัตถุดิบในชุดหลัก
  qty         numeric not null,
  unit        text not null,              -- ล็อกหน่วย ห้ามให้ครัวพิมพ์เอง
  counted_at  timestamptz default now(),
  counted_by  text,
  note        text
);
alter table ing_counts enable row level security;
create policy "ing_counts_all_anon" on ing_counts for all using (true) with check (true);
```
⚠️ **ตารางต้องขึ้นต้นด้วย `ing_` เสมอ** — เป็นเขตที่จองไว้ให้ ไม่ชนใคร

## 5. โค้ดตัวอย่างที่ใช้ได้จริงในระบบนี้

```js
/* อ่าน/เขียน kitchen_data (เขียนได้เลย ไม่ต้องรัน SQL) */
const { data } = await sb.from('kitchen_data').select('data').eq('key','ing_settings').maybeSingle();
await sb.from('kitchen_data').upsert({ key:'ing_settings', data:{ ...} }, { onConflict:'key' });

/* 🔴 ดึงเกิน 1,000 แถวต้องไล่หน้าเอง — ไม่ทำ = ข้อมูลหายเงียบ ไม่มี error
   (เคยทำให้ครัวมองไม่เห็นออเดอร์ทั้งวันมาแล้ว) */
let rows = [], from = 0;
for(;;){
  const { data } = await sb.from('orders').select('*').range(from, from+999);
  rows = rows.concat(data||[]);
  if(!data || data.length < 1000) break;
  from += 1000;
}

/* 🔴 เวลาไทยเสมอ — เจ้าของอยู่ต่างประเทศ ใช้นาฬิกาเครื่องจะได้คนละวัน */
const todayTH = new Date(Date.now() + 7*3600e3).toISOString().slice(0,10);

/* จดประวัติ — ไม่บังคับ แต่จดแล้วของคุณจะโผล่ในหน้าประวัติที่มีอยู่แล้วเอง */
try{ await sb.from('activity_log').insert({
  actor:'ชื่อคนกรอก', source:'ing', action_type:'stock',
  summary:'นับวัตถุดิบ กระเทียม 5→12 กก.', detail:{ item:'กระเทียม', from:5, to:12 }
}); }catch(e){}
```

**❗ `204 No Content` ไม่ได้แปลว่าเขียนสำเร็จ** — RLS บล็อกเงียบได้ → **นับซ้ำจากฐานข้อมูลหลังเขียนเสมอ**

**ห้ามเขียนทับของห้องการเงิน** (อ่านได้): `ingredient_prices` · `docs/INGREDIENT_*` · `kitchen_data.f_*` · `supplier_orders_*`
**ห้ามเขียนทับของห้อง u**: `kitchen_data.ingredients` · `kitchen_data.recipes` (หน้า DB ใช้อยู่ — อ่านได้ ต่อยอดได้ แต่เขียนทับไม่ได้)

**ห้ามเด็ดขาด ไม่ว่าใครสั่ง**
- `menu_items.is_available` (เปิด/ปิดขายเมนู) — เจ้าของเคาะเท่านั้น
- `menu_items.stock_total` / `actual_stock` — สต็อก**เมนู** มาจากการนับของครัวเท่านั้น (คนละเรื่องกับวัตถุดิบ)
- ส่งข้อความหาลูกค้า (LINE push / broadcast) — เจ้าของกดเอง
- **ลบแถว** ในตารางลูกค้า/ออเดอร์ — ปิดสถานะได้ ลบไม่ได้

**เขียนข้อมูลจริงทุกครั้ง: สำรองก่อน → รันเปล่าให้ดูก่อน (`--apply`) → นับซ้ำจาก DB หลังเขียน**

## 8. ส่งอะไรกลับมาเมื่อขึ้นของแล้ว (ห้อง u ต่อให้ภายในวันเดียว)

1. **ชื่อไฟล์หน้าเว็บ** ที่ขึ้นแล้ว (เช่น `pwa/ing_stock.html`) + อยากได้เส้นทางสั้นว่าอะไร
2. **ตาราง/คีย์ที่ใช้** ทั้งหมด (ถ้ามี SQL ส่ง SQL มาด้วย)
3. **ใครเป็นคนใช้** — ครัว / เจ้าของ / ทั้งคู่ (u จะได้แปะลิงก์ให้ถูกที่)

จากนั้น u จะ: เพิ่มเส้นทาง · แปะลิงก์ในหน้ารวมของครัวและห้องนัท · ตรวจให้ 1 รอบว่าไม่ชนของใคร แล้วแจ้งกลับ
