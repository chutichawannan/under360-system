## ขั้นตอน (ก๊อปวางได้เลย)

```bash
git checkout -b fix/ชื่องานสั้นๆ
```
```bash
git add ไฟล์ที่แก้ && git commit -m "ข้อความสั้นๆ ภาษาไทย" && git push -u origin HEAD
```
→ **Vercel สร้างลิงก์ทดสอบของ branch นี้ให้เองอัตโนมัติ** (คนละลิงก์กับของจริง — ลูกค้าไม่เห็น)
→ เปิดลิงก์นั้นบนมือถือจริง เทสให้ผ่าน

```bash
git checkout main && git merge fix/ชื่องานสั้นๆ && git push
```
```bash
git branch -d fix/ชื่องานสั้นๆ && git push origin --delete fix/ชื่องานสั้นๆ
```

## 🚨 ช่องฉุกเฉิน — ใช้เมื่อไหร่

**ใช้ได้เฉพาะเมื่อ "ลูกค้าเดือดร้อนอยู่ตอนนี้"** เท่านั้น:
- ลูกค้าสั่งของไม่ได้
- ครัวไม่เห็นออเดอร์ / เห็นผิด
- ของจะไม่ถึงมือลูกค้า
- เงินคิดผิด

```bash
HOTFIX=1 git push origin HEAD:main
```

**ใช้แล้วต้องแจ้งบอร์ดทันที** ว่าแก้อะไร ทำไมถึงด่วน — ไม่ใช่แก้เงียบๆ

**ไม่ใช่เหตุฉุกเฉิน:** ปุ่มไม่สวย · คำผิด · อยากได้ฟีเจอร์เพิ่ม · "แก้นิดเดียว" · "รีบ"

## ทำไมไม่ต้องรอนัทอนุมัติ (แบบ B ที่รวมอยู่ใน C)

นัทเลือกให้**ห้องอนุมัติกันเองได้** — ไม่ต้องรอนัทกดทุกครั้ง เพราะนัทจะกลายเป็นคอขวด
สิ่งที่นัทขอแทนคือ: **เทสจริงก่อน merge** และ **ห้ามแก้ของจริงตรงๆ**

## ระบบบังคับ (ไม่ใช่แค่ขอความร่วมมือ)

มี hook `pre-push` ที่ `.githooks/pre-push` — **ยิงขึ้น main ตรงๆ จะถูกปฏิเสธทันที** พร้อมบอกวิธีที่ถูก

เปิดใช้ด้วย (ทำครั้งเดียวต่อเครื่อง — ทำไว้แล้ว):
```bash
git config core.hooksPath .githooks
```

> ทุกห้องใช้ repo เดียวกันบนเครื่องเดียวกัน → ตั้งครั้งเดียวมีผลทุกห้อง รวม worktree ด้วย

## ข้อควรรู้เพิ่ม

**1 branch = 1 เรื่อง ไม่ใช่ 1 เวอร์ชัน**
หลาย branch วิ่งพร้อมกันได้ — U แก้เรื่องนึง P แก้อีกเรื่อง คนละสาขา ไม่ชนกัน

**branch อยู่ให้สั้นที่สุด**
แยกออกมาแล้วรีบ merge กลับ · ทิ้งไว้นานเท่าไหร่ ยิ่งชนกับคนอื่นง่าย

**ยังใช้กติกาเดิมทั้งหมด**
- จองงานใน `work_claims` ก่อนลงมือ · เจอคนจองแล้ว = ไม่ทำ
- ปิดงานต้องมีหลักฐานที่ query ซ้ำได้
- แก้ในไฟล์บ้านคนอื่น = ถามเจ้าของก่อน
- `node -e` + ข้อความไทยมี backtick = shell กินทิ้ง → เขียนเป็นไฟล์ `.mjs`
