## 1. ห้องนี้ทำอะไร (JD เบื้องต้น — นัทเคาะเอง)

> **"เอางานที่มีเนี่ยแหละ มาทำแพลนส่ง และตรวจเช็ครายการที่ต้องส่งว่ามาครบไหม 3 ทาง"**

**หน้าที่หลัก 2 อย่าง:**

### ① ทำแพลนส่งประจำวัน
เอางานส่งของวันนั้น → จัดรอบ → บอกว่าควรเรียก Lalamove กี่คัน คันไหนแวะที่ไหนบ้าง ราคาเท่าไหร่

### ② ตรวจว่ารายการที่ต้องส่ง "มาครบไหม" — เทียบ 3 ทาง
| ทาง | ที่อยู่ | ใครเป็นเจ้าของความจริง |
|---|---|---|
| **หน้าออเดอร์ (OH)** | `operation_hub.html` → แท็บออเดอร์/แมสเซนเจอร์ · ตาราง `orders` | ระบบเรา |
| **หน้าครัว (KQ)** | `kitchen_queue.html` · กรองด้วย `delivery_date` | ครัวใช้จัดของ |
| **ชีทของแอดมิน** | Google Sheet ด้านล่าง | **ตอนนี้คือความจริงตัวจริง** |

**🔴 3 ทางนี้ไม่ตรงกันจริง และนั่นคืองานหลักของห้องนี้** — ดูหัวข้อ 4

## 3. เครื่องมือที่มีแล้ว (ใช้ได้เลย ไม่ต้องสร้างใหม่)

### `api/lalamove-quote.js` — ขอราคาจริงจาก Lalamove v3
```
จุดเดียว    GET  /api/lalamove-quote?lat=13.72&lng=100.57&addr=...
หลายจุด     POST /api/lalamove-quote   body {"drops":[{lat,lng,addr},...]}
สเปครถ      GET  /api/lalamove-quote?info=cities
```
· **ขอราคาอย่างเดียว ไม่จองรถ ไม่มีการใช้เงิน**
· `service` เลือกได้ (default `MOTORCYCLE`)

### ปุ่ม "💰 คำนวณค่าส่งถูกสุด" — `operation_hub.html` แท็บแมสเซนเจอร์
เลือกวัน → กด → ได้แผนจัดรอบ + ราคาจริง + บันทึกสถิติอัตโนมัติ
อัลกอริทึมข้างใน (อ่านโค้ดก่อนแก้ — comment อธิบายไว้ครบ):
1. จับกลุ่มโดย **ไล่ทุกวิธีผสมข้ามทิศ** (DP บิตมาสก์) ไม่ใช่หั่นตามลำดับ
2. **เรียงลำดับแวะให้ระยะสั้นสุดก่อนขอราคา** (Lalamove คิดตามลำดับที่เราส่งไป)
3. ขอเรท "รวมรอบ" กับ "ยิงแยก" **ติดกัน** → รอบไหนรวมแล้วไม่ถูกลง **แตกออกอัตโนมัติ**
4. แยกรอบตาม **ช่วงเวลาที่รับปากลูกค้า** (รวมข้ามช่วงถูกกว่านิดเดียวแต่ลูกค้าได้ของช้า = ไม่เอา)

### `delivery_cost_log` — สถิติค่าส่งรายวัน
❌ **ตารางนี้ไม่ได้ใช้แล้ว — ไม่ต้องรัน SQL** (เช็คสด 15 ส.ค. REST ยังตอบ 404 และจะเป็นแบบนั้นต่อไป)
U ย้ายไปเก็บใน **`kitchen_data`** คีย์ `delivery_cost_YYYY-MM-DD` แทน เพราะตารางใหม่ต้องรอนัทรัน SQL ซึ่งค้าง 2 วัน
→ **เก็บได้จริงแล้ว 8 วัน** (6-14 ส.ค.) · บันทึกเองทุกครั้งที่กดปุ่ม 1 วัน 1 แถว
เป้าหมาย: สะสมให้ครบ 20-30 วัน → ตอบได้ว่า **จ้างแมสเงินเดือนเท่าไหร่ถึงสมเหตุสมผล**

## 4. 🔴 ปัญหาที่ค้างอยู่ — นี่คือเหตุผลที่ห้องนี้เกิด

### ก. 3 ทางไม่ตรงกัน (วัดจริง 5 ส.ค. 2569)
```
ชีทแอดมิน   15 งาน Lalamove + 1 NIM = 16
Hato        12 ใบ
ระบบเรา     12 ใบ  (ตรงกับ Hato เป๊ะ)
```
**ต่าง 6 ใบ = ลูกค้าคอร์ส** (ธนัทพร · สุทธิภา · อุษณี · พรหมพงศ์ · โมจิ · Bright)
**สาเหตุ:** คอร์ส = 1 ออเดอร์ ส่งหลายรอบ แต่ `orders.delivery_date` เก็บได้ค่าเดียว → รอบ 2,3,4 หายจากทุกหน้าที่กรองด้วยวันที่
· แอดมินทำ **2 มาตรฐาน** — บางเคสเปิด "ใบแยกวันส่ง" (ระบบเห็น) บางเคสจดในชีทเฉยๆ (ระบบไม่เห็น)
· **P ยืนยันแล้วว่า Hato ก็ไม่มีข้อมูลรอบส่ง** (ขุด 4 ชั้น) → ไม่ใช่ sync ขาด
· **ข่าวดี: ชีทไม่ตายพร้อม Hato** → ยัง backfill ได้หลัง cutover

### ข. ⚠️ วันที่ 5 มี "ใบเกิน" ที่ยังไม่จบ — **ห้ามเอาตัวเลขวันที่ 5 ไปอ้างจนกว่า P จะเคลียร์**
P generate `MP-*` **82 ใบพร้อมกัน** (5 ส.ค. 06:14) กระจายวันส่งถึง **พ.ย. 2026**
· 6 ใบแรกถูกต้อง (เติมคอร์สที่ขาด) · **แต่เกินมาอย่างน้อย 3 ใบ** ที่ไม่มีในชีทแอดมิน (โอ๋ 2 ใบวันเดียวกันจากใบแม่เดียวกัน · ฝน 1 ใบไม่มีใบแม่)
· **นัทโวยเรื่องนี้ไปทาง P แล้ว · U ถามในบอร์ดแล้ว · ยังไม่มีคำตอบ**
· ถ้ากติกา generate ผิด **วันอื่นเกินด้วย** (7 ส.ค. 8 ใบ · 10 ส.ค. 6 ใบ ...)

### ค. ยังไม่รู้น้ำหนักของต่อใบ
`order_items` ไม่ครบ → เช็คไม่ได้ว่ารอบไหนเกิน 20 กก. (เพดานมอเตอร์ไซค์)
**นัทบอกแล้วว่า "3 คนไม่มีทางเกิน 20 โล" → เพดาน 3 ปลอดภัยอยู่แล้ว ไม่ต้องกังวล**

### ง. ยังไม่มีต้นทุนแมสร้านต่อเที่ยว
ฝาก f-track ไว้แล้ว · ไม่มีเลขนี้ = เทียบไม่ได้ว่าเมื่อไหร่จ้างแมสคุ้มกว่ายิง Lalamove

## 6. รูปแบบ output ที่นัทชอบ (ทำตามนี้)

> นัทพูดเอง: *"ฉันชอบแบบนี้มากเลย ที่นายทำ ที่ฉันเล่าให้ฟังว่าจะให้นายลองเรียงงานดู แล้วนายพล้อตแมพเลย"*

**สูตร = เรียงงานเป็นรอบ + พล็อตแมพให้เห็นว่าอะไรใกล้อะไร**

**นัทยืนยันว่าชอบทั้ง 2 แบบ — ทำคู่กันไปเลย ไม่ต้องเลือก:**

## 7. กติกาห้อง (ทุกห้องใช้ร่วมกัน)

1. **จองงานก่อนทำ** — `work_claims` (task/room/files) · เจอคนจองแล้ว = ไม่ทำ ให้ถามเจ้าของ
2. **รายงานที่บอร์ด** — ตาราง `session_messages` (room / sender / role / text) · ห้อง `u` = U-track, `cc` = เลขา
3. **แบ่งงานตามเจ้าของไฟล์** — U = `operation_hub` · `kitchen_queue` · `main_database_v2` · `liff_*` · P = สคริปต์ sync/ข้อมูล Hato · CC = `docs/` + ประสาน
   **เจอบั๊กบ้านคนอื่น = ส่งให้เจ้าของ ห้ามแก้เอง** (เพิ่งเกิดเคสแก้ทับกันจริง นัทโวย)
4. **ห้ามสลับ branch ในทรีหลัก** — ใช้ worktree เสมอ (งานหายจริงมาแล้ว 2 รอบ)
5. **verify กับ `origin/main` + DB สดก่อนพูด** — working tree ไม่ใช่ความจริง · เอกสารเป็น snapshot
6. **push แล้ว verify ก่อนลบ worktree**
   ```
   git push origin HEAD:main && git fetch origin main
   git show origin/main:<file> | grep -c "<marker>"   # ต้อง >0
   ```
7. **1000-cap** — `.select()` ไม่มี `.limit()`/`.range()` → Supabase คืนแค่ 1000 แถวเงียบๆ · `orders` มี 15,900+ ใบ

   (⚠️ อย่าเพิ่งใช้วันที่ 5 เป็นตัวอย่าง — ยังมีใบเกินค้างกับ P)
2. **ทำแพลนส่งพรุ่งนี้** ในรูปแบบข้อ 6 (เรียงรอบ + แมพ)
3. **กดปุ่มคำนวณทุกวัน** เพื่อสะสมข้อมูลตอบเรื่องจ้างแมส (เก็บลง `kitchen_data` อัตโนมัติ ไม่ต้องรัน SQL อะไรแล้ว)

**อย่าเพิ่งทำ:** place order จริง (ใช้เงิน · รอนัท) · แตะข้อมูล `MP-*` (บ้าน P · ยังไม่จบ)
