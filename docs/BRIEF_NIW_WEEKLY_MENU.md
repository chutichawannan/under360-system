## 1️⃣ เงื่อนไขการเลือกเมนู (นัทวางเอง ห้ามเปลี่ยน)

| | |
|---|---|
| **จำนวน** | ข้าวกล่อง **8 ตัว (S1–S8)** + แพคกับข้าว **5 ตัว (D1–D5)** |
| **ไม่ซ้ำ** | **อย่างน้อย 3 เดือน** |
| **สัดส่วน** | **สัตว์บก 6 · สัตว์ทะเล 2–3** |
| **ต้องมีรูป** | ไม่มีรูป = ใช้ไม่ได้ (นัททำโบรชัวร์ไม่ได้) |

**เพิ่มเติมที่ควรทำ (ไม่ใช่กฎ แต่นัทชอบ):**
- **สไตล์ไม่ซ้ำกัน** — อย่าให้เป็นผัด 5 ตัว · ควรมีทั้ง ย่าง/ยำ/แกง/อบ/เส้น/พาสต้า
- **มีเมนูไม่ใช่ข้าว 2–3 ตัว** (เส้นหมี่ · พาสต้า) กันลูกค้าเบื่อ
- **คุมราคา** — ทะเลตัวละ ~฿169 · บก ฿110–130 · ใส่ทะเล 3 ตัว = ต้นทุนสัปดาห์ขยับ **ร้านกำลังตึงเรื่องเงินสด ให้ระวัง**

## 2️⃣ วิธีเช็ค "ซ้ำ 3 เดือน" — ต้องดู 2 แหล่ง ไม่ใช่แหล่งเดียว

**แหล่ง A — แท็กสัปดาห์ในระบบ (แม่นสุด แต่มีแค่ ก.ค. เป็นต้นมา)**
```
kitchen_data.menu_special_weeks  →  { "S022": "2026-08-10", ... }   // code → วันจันทร์ของสัปดาห์นั้น
```

**แหล่ง B — ออเดอร์จริง (ครอบคลุมทุกช่วง)**
```
order_items JOIN orders  ที่ orders.delivery_date >= (วันนี้ - 3 เดือน) และ status != 'cancelled'
```

🔴 **ต้องกรองทั้ง `menu_code` และ `menu_name`** — เมนูเดียวกันมีหลายรหัส (เช่น ลาบแซลมอนเป็นได้ทั้ง `S043` และ `D043`) ถ้าเช็คแค่รหัสจะปล่อยของซ้ำหลุด

**แหล่ง C — ประวัติเก่ากว่านั้น (ม.ค.–เม.ย.)** อยู่ในชีท Google `All menu+แพลนเมนูอาทิตถัดไป`
`fileId = 16BHkCegHHTcOQkgDqPHlDRvW0fLu1nOKLBZpQ9PmNM4` (เจ้าของ: พลอย) — แถวที่ขึ้นต้นด้วย `313. 12-18/1/2026` คือประวัติรายสัปดาห์

📌 **ข้อมูลอ้างอิง:** ร้านหมุนซ้ำทุก ~2–5 เดือนเป็นปกติ → กฎ 3 เดือนสอดคล้องกับที่ทำจริง ไม่ได้ตั้งลอยๆ

## 3️⃣ จับคู่ D กับ S — 🔴 **ห้ามใช้รหัส ให้ใช้ชื่อ**

เดิมเข้าใจกันว่า *"S กับ D เลขตรงกัน = เมนูเดียวกัน"* — **ตรวจแล้วไม่จริง**
**มี 46 คู่ที่เลขตรงแต่คนละเมนู** (ดู `docs/AUDIT_SD_CODE_MISMATCH.md`)

| ตัวอย่างที่พังจริง | |
|---|---|
| `S157` ผักกาดห่ออกไก่ | `D157` **กุ้งผัดต้มยำแห้ง** ❌ |
| `S063` ไก่ย่างพริกสามรส | `D063` **อกไก่ผัดเปรี้ยวหวาน** ❌ |

**แพทเทิร์น:** รหัสต่ำกว่า 100 ผิด 11% · **ตั้งแต่ 100 ขึ้นไปผิด 83%** (กติกาถูกเลิกใช้ไปเองตั้งแต่ยุครหัส 100+)
→ **ผลกระทบ: ถ้าจับคู่/ยืมรูปด้วยเลข จะได้ผิดชนิดโปรตีน = เสี่ยงเรื่องของแพ้**
→ **วิธีที่ถูก: หา D ที่ "ชื่อตรงกับ S" ไม่ว่าเลขจะเป็นอะไร**

⏳ **ยังค้างรอนัทเคาะ:** จะแก้คู่ที่ผิดแบบ **A) ย้ายรหัสให้เลขตรง** (เสี่ยงประวัติออเดอร์เพี้ยน) หรือ **B) ไม่แตะรหัส แค่บันทึกคู่ไว้** — ถามนัทก่อนลงมือ

## 4️⃣ ลงระบบ — คำสั่งเดียวจบ

```bash
# 1. ก๊อปไฟล์ตัวอย่าง ตั้งชื่อตามวันจันทร์ของสัปดาห์นั้น
cp scripts/weeks/2026-08-17.json scripts/weeks/2026-08-24.json
# 2. แก้ 13 บรรทัดในไฟล์ (sub / code / name / price)
# 3. พรีวิวก่อน — ไม่แตะข้อมูล
node scripts/weekly_menu_deploy.mjs scripts/weeks/2026-08-24.json
# 4. ลงจริง + audit + เทสสั่ง
node scripts/weekly_menu_deploy.mjs scripts/weeks/2026-08-24.json --go
```

**สคริปต์ทำให้ครบ 6 ขั้น** — เช็คลิสต์ถูกฝังในโค้ดแล้ว **ลืมไม่ได้**:
1. เปิดขาย + หมวด (`no_special` / `pack_regular`) + ชื่อเล่น + ธง + ราคา + แคล
2. **ล้างชื่อเล่นรอบเก่า** (กติกานัท: **1 ชื่อเล่น = 1 เมนู** · มีของใหม่ = ของเก่าต้องถูกลบชื่อเล่น เหลือแค่รหัสจริง) — **แต่คงแท็กสัปดาห์เดิมไว้** เพื่อให้ลูกค้ารู้ว่าเป็นของรอบไหน
3. แท็กสัปดาห์ลง `kitchen_data.menu_special_weeks`
4. **+฿40 อาหารทะเลใน Diet Set A/B/C** → เขียนที่ `package_items.extra_price` **ห้าม hardcode ในโค้ด** (นัทสั่งเอง: *"หน้าหลังบ้านคือหน้าคนทำจริง ถ้าไปออกโค้ดหลังบ้าน ต้องมาแก้กันอีก"*)
5. **AUDIT** — รวมข้อที่เคยลืมทุกครั้ง: **เซ็ต Diet A/B/C กับ Protein Pack S/M/L สั่งเมนูใหม่ได้ไหม**
6. **เทสสั่งจริง 1 ใบ** → อ่านกลับแบบหน้าครัว → ยกเลิกใบเทส

📌 **`node` ไม่อยู่ใน PATH** — ใช้ `"C:/Program Files/nodejs/node.exe"`

## 5️⃣ 🪤 กับดักที่โดนมาแล้วจริง — อ่านก่อนแตะข้อมูล

| กับดัก | อาการ | ทางแก้ |
|---|---|---|
| **`stock_total = null` แปลว่า "ไม่จำกัด" ไม่ใช่ "หมด"** | เช็ค `!stock_total` แล้วปิดเมนูไม่จำกัดทิ้งหมด = หายนะ | ต้องแยก `null` / `0` / `N>0` |
| **PATCH/DELETE คืน `204 สำเร็จ` ทั้งที่ไม่มีแถวถูกแตะ** | เขียนแล้วนึกว่าเสร็จ แต่ข้อมูลไม่เปลี่ยน | **query กลับมานับทุกครั้ง** อย่าเชื่อ status code |
| **ลบ `orders` ผ่าน anon ไม่ได้** (ไม่มี RLS policy) | DELETE คืน 204 แต่แถวยังอยู่ | ใช้ `PATCH status='cancelled', total=0` แทน · ⚠️ `delivery_date=null` ไม่ได้ (NOT NULL) |
| **`.select()` ไม่มี `.limit()` → คืนแค่ 1,000 แถว** เงียบๆ | นับยอดขาดโดยไม่มี error | paginate ด้วย `.range()` เสมอ |
| **curl + ข้อความไทยบน Windows** | ได้ `???` / HTTP 400 | เขียน JSON ลงไฟล์แล้ว `--data-binary @file` |

## 6️⃣ 📸 เรื่องรูป — สิ่งที่นัทต้องใช้ทำโบรชัวร์

- **รูปใน Storage เป็น 800×800** (ดูดจากโบรชัวร์เก่า) — **นัทบอกเองว่าไม่ชัดพอทำโบรชัวร์ใหม่**
- **Hato มีต้นฉบับ 1024×1024 ครบ 630/638 เมนู** — เทียบ 30 ตัวสุ่ม: **Hato ชัดกว่า 28 · เสมอ 2 · เราชนะ 0**
- แคตตาล็อก Hato ดึงเก็บไว้แล้วที่ `kitchen_data.hato_catalog_dump` (638 รายการ · `{sku, n, a, img, cnt}`)
  ⚠️ `img` เป็น **template** — ต้องแทน `{width}x{height}` ด้วย `1024x1024` ไม่งั้นได้ HTTP 502
- 🔴 **งาน migrate รูปยังไม่ได้ทำ** — ถ้าจะทำ **ต้องจับคู่ด้วยชื่อ ไม่ใช่เลข** (ดูข้อ 3)

**ระหว่างที่ยังไม่ migrate — สิ่งที่นิวต้องส่งให้นัททุกสัปดาห์:**
> เมนูแต่ละตัว **เคยลงสัปดาห์ไหน** (เลข week + ช่อง S ที่เท่าไหร่) → นัทเอาไปเปิดคลังรูปเดิมดึงต้นฉบับเอง
> จัดกลุ่มตาม week ให้ด้วย จะได้เปิดโฟลเดอร์น้อยที่สุด
