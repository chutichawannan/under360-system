> *"เราจะโฟกัสกันที่ **S2** เป็นหลักก่อน เพราะว่าฉันจะให้**โม๋ข่องเฝ้าสินค้านี้ต่อเนื่อง 3 วัน** เพื่อหาให้เจอว่าปัญหาที่ไหน"*

**S2 = S062 ข้าวคั่วกลิ้งอกไก่แครนเบอร์รี่ไข่ต้ม** · สัปดาห์ W37

## 📸 หน้าจอที่ครัวเห็นเช้านี้ (10 ก.ย.) — ของจริง

```
S062 · S2 · W37   ข้าวคั่วกลิ้งอกไก่แครนเบอร์รี่ไข่ต้ม
มีจริง 4  +  กำลังเติม 0  –  สั่งแล้ว 4      →  ขายได้ 0
รูปหน้าคน 4 รูป
```
**นับในตู้เย็นจริงตอนนั้น = 3**

## 🧩 ปัญหาที่นัทไล่มา — **คำต่อคำ ห้ามตีความ ห้ามย่อ**

### ① เลขบนจอกับของในตู้ไม่ตรง
> *"ปัญหาของ S2 และทุกรายการ เกิดขึ้นที่ในระบบของมือถือพนักงานครัว เห็นตอนนี้ว่า**มีจริงทั้งหมด 4 แต่นับในตู้เย็นตอนนี้ดันมี 3**"*

### ② ของ 4 ชิ้นนั้น "ถูกจัดไปแล้ว" — แล้ว 3 ที่เหลือคือของใคร
> *"ไม่ใช่แค่นี้ เพราะว่า**มีจริง 4 และมีรูปหน้าคนทั้งหมด 4** แปลว่านอกจากมีจริงแล้ว รายการนี้**ถูกจัดไปเรียบร้อยแล้ว** ดังนั้นทั้ง 4 รายการนี้ควรจะอยู่ในถุงอาหารที่ถูกแพ็คไว้แล้ว และ**เราไม่รู้ว่าถูกส่งไปหรือยัง หรือยังอยู่ในครัว** และ 3 รายการที่ยังเหลืออยู่ในตู้เย็น **มันควรจะเป็นของ 4 คนนั้น หรือว่ามันเป็นของที่เหลือขึ้นมาจริงๆ**"*

### ③ จะเพิ่มของที่เหลือกลับเข้าระบบยังไง — ตอนนี้ใช้ช่องผิดความหมายอยู่
> *"ปัญหาที่ตามมาก็คือ**เราจะเพิ่มสต๊อกยังไง ช่องไหนดี** ตอนนี้แก้ปัญหาเบื้องต้นโดยการให้โม๋ข่องแจ้งลงไปในระบบว่า**ทำเพิ่ม 3** ซึ่งจริงๆ **เราไม่ได้ทำเพิ่มขึ้นมา 3 หรอก แต่เรามีเหลือ 3** เราเลยใส่เติมเข้าไปว่าทำเพิ่ม 3 ซึ่งเราก็ไม่รู้ว่าจะมีปัญหาตามมาไหม"*

### ④ 3 ที่เหลือ อาจเป็นของที่ยังไม่ได้จัด — แต่ก็ไม่ควรมีของเหลือตอนเช้า
> *"เช่น เอ้ย จริงๆ 3 อันนี้**ควรจะถูกจัดให้ลูกค้าแต่ว่ายังไม่ได้จัด** ซึ่งอันนี้ก็มีความเป็นไปได้ และก็มีความเป็นไปไม่ได้เช่นกัน เพราะว่า**ทุกๆ วันควรจัดของตอนจบวัน** ซึ่งตอนนี้มันเป็น**เริ่มต้นเช้าวันใหม่ ไม่ควรมีของเหลือ 3**"*

### ⑤ ไม่รู้ว่าลูกค้าสั่งตอนไหน สต๊อกถูกตัดเมื่อไหร่
> *"ยังจะมีปัญหาแทรกซ้อนอีกเยอะมาก **ไม่รู้ลูกค้าสั่งตอนไหน ถูกตัดสต๊อกไปเมื่อไหร่** บางทีก็อาจจะมีเหตุการณ์เช่น มีจริง 3 ลูกค้ากดสั่งมาตอนกลางคืนที่ครัวเลิกงาน ก็อาจจะกลายเป็นมีจริง 4 ที่ถูกจัดเข้าไป ทำให้สต๊อกเป็นศูนย์ อันนี้ก็คิดมั่วไปหมด"*

### ⑥ งานจัดของระหว่างวันของกิ๊ฟ
> *"ระหว่างวันกิ๊ฟสั่งให้ครัวจัดของให้ลูกค้า ซึ่งก็ต้องมาดูกันอีกว่า**จัดจากรายการที่ถูกหักสต๊อกไว้แล้ว หรือว่ามีลูกค้ามาสั่งด่วน**"*

## 🗝️ คำตอบจากกิ๊ฟ (แอดมิน) — **นัทถามเองแล้ว · หลักฐานชั้นต้นที่สำคัญที่สุดของ issue นี้**

> *"มีค่ะแต่ไม่บ่อย ส่วนมาก**ที่สต๊อกไม่ตรงเพราะ order ลูกค้าบางคนขาด ก็จะให้ลูกค้าเลือกเมนูใหม่ทดแทน** อาจจะเป็นส่วนที่ทำให้สต๊อกไม่ตรง · **กรณีการตัดสต๊อกของหนูคือตัดแมนนวล โดยเข้าหลังบ้านแล้วลบเอาเลยค่ะ**"*

🔴 **อ่านให้ดี:** มีการเปลี่ยนสต๊อกที่**ไม่ได้ผ่านทางที่ระบบออกแบบไว้** และ**ไม่ได้ผ่านหน้าครัว** — ทุกห้องต้องไล่ว่าการ "ลบเอาเลยที่หลังบ้าน" ไปโผล่/ไม่โผล่ที่ไหนบ้าง

⚠️ **ห้ามตีความว่ากิ๊ฟทำผิด** — กิ๊ฟทำเพราะไม่มีทางอื่นให้ทำ **ที่ผิดคือระบบไม่มีช่องให้** (กฎบ้านนี้: ระบบที่บังคับให้คนเลี่ยง = ระบบออกแบบพลาด)

### 🎯 สิ่งที่ต้องตอบให้ได้ก่อนจบประชุม
1. **เลข "มีจริง" หมายความว่าอะไรกันแน่** — ของในตู้ ? ของที่ทำเสร็จวันนี้ ? ของที่ยังไม่ถูกจอง ?
2. **"สั่งแล้ว 4" + "รูปหน้าคน 4" หักออกจาก "มีจริง" ไปแล้วหรือยัง** หรือหักซ้ำ/ไม่หักเลย
3. **มีกี่ทางที่เลขนี้ขยับได้** — ลูกค้ากดสั่ง · ครัวกรอก · ปิดวันอัตโนมัติ · กิ๊ฟลบที่หลังบ้าน · อื่นๆ **ไล่ให้ครบทุกทาง**
4. **ทางไหนบ้างที่ขยับแล้วไม่มี log** = จุดที่ตามไม่เจอตลอดกาล
5. **ของเหลือจริงตอนเช้า ควรลงช่องไหน** ("ทำเพิ่ม" ที่ใช้อยู่ตอนนี้ ทำให้อะไรพังตามมาบ้าง)

### ② 🔴 **ลูกค้ากดสั่ง = ไม่มี log สักแถวเดียว** ทางที่เลขขยับบ่อยที่สุดคือทางที่มองไม่เห็น
```
เหตุที่ทำให้เลขไม่ตรง : เวลาลูกค้ากดสั่ง สต๊อกถูกตัด แต่ไม่มีบันทึกว่าใครสั่ง ตัดกี่ชิ้น ตอนกี่โมง
                       ตอบคำถามข้อ 5 ของนัท ("ไม่รู้ลูกค้าสั่งตอนไหน ถูกตัดสต๊อกเมื่อไหร่") ไม่ได้เลย
                       **ไม่ใช่หาไม่เจอ แต่ไม่เคยถูกบันทึก**
หลักฐาน              : activity_log เดือน ก.ย. action_type มีแค่ stock(337) order_move(24) kq_status(8)
                       log สต๊อก 337 แถว แยกตาม source: kq 331 / db 5 / k 1
                       **ไม่มี source จากฝั่งลูกค้า (LIFF) เลยสักแถว**
เกิดตอนไหนของวัน      : ทุกครั้งที่ลูกค้าสั่ง โดยเฉพาะกลางคืนหลังครัวเลิกงาน (เคสที่นัทยกเอง)
ใครทำให้เลขขยับ       : ลูกค้า
```

### ③ 🔴 **"ปิดวันอัตโนมัติ" ถูกบันทึกในชื่อคน** เฝ้า 3 วันแล้วจะโทษโม๋ข่องผิด
```
เหตุที่ทำให้เลขไม่ตรง : เหตุการณ์ที่ระบบทำเอง ถูกบันทึกว่าเป็นคนทำ เพราะมันวิ่งตอนคนเปิดหน้าจอ
                       06 ก.ย. 06:21  S062 "ปิดวันอัตโนมัติ" -> actor = MoKHAUNG
                       08 ก.ย. 02:02  S062 "ปิดวันอัตโนมัติ" -> actor = ระบบ (ปิดวัน)
                       เหตุการณ์เดียวกัน คนละชื่อ
หลักฐาน              : เดือน ก.ย. มี "ปิดวันอัตโนมัติ" 64 ครั้ง แต่ actor = "ระบบ (ปิดวัน)" แค่ 38 ครั้ง
                       **อีก 26 ครั้งไปอยู่ในชื่อคน**
เกิดตอนไหนของวัน      : ครั้งแรกที่มีคนเปิดหน้าครัวของวันนั้น เวลาไม่คงที่ (01:51 / 02:02 / 03:09 / 06:21 UTC)
ใครทำให้เลขขยับ       : ระบบเอง แต่ log บอกว่าเป็นครัว
```
⚠️ **ข้อนี้กระทบวิธีที่นัทเลือกโดยตรง** ถ้าโม๋ข่องเฝ้า 3 วันแล้วเอา log มาดู จะเห็นชื่อตัวเองอยู่บนเหตุการณ์ที่ตัวเองไม่ได้ทำ

### ④ ใบที่ถูกยกเลิก ไม่มีการคืนของกลับเข้าสต๊อก
```
เหตุที่ทำให้เลขไม่ตรง : S062 มีใบที่ยกเลิกไปแล้ว 1 ใบ แต่ประวัติสต๊อกทั้งเดือนไม่มีเหตุการณ์ "คืนสต๊อก" เลย
                       ของที่เคยถูกกันไว้ให้ใบนั้น ยังถูกกันอยู่ หรือหายไปเลย ตอบไม่ได้

                       ชนิดเหตุการณ์ทั้งหมดในประวัติสต๊อก ก.ย.: แก้จำนวน / เติมสต็อค / ปิดวันอัตโนมัติ /
                       ซ่อนการขาย / เปิดขายคืน / เติมเสร็จ  -> **ไม่มีคำว่า "คืน" อยู่เลย**
เกิดตอนไหนของวัน      : ตอนแอดมินยกเลิก/สลับเมนูให้ลูกค้า
                       ตรงกับที่กิ๊ฟเล่าว่า "order ขาด ให้ลูกค้าเลือกใหม่ทดแทน"
ใครทำให้เลขขยับ       : กิ๊ฟ / แอดมิน
```

### ⑤ ที่กิ๊ฟบอกว่า "ไม่บ่อย" ตัวเลขบอกว่าเกือบทั้งหมด**ไม่ได้ถูกบันทึก** ไม่ใช่ว่าไม่ได้เกิด
```
เหตุที่ทำให้เลขไม่ตรง : การแก้จากหลังบ้านแทบไม่ทิ้งร่องรอย เทียบเลขย้อนหลังไม่ได้
หลักฐาน              : เดือน ก.ย. log สต๊อกที่มาจากหน้าหลังบ้าน (source=db) = **5 แถว**

                       เทียบกับงานสลับเมนู/ยกเลิกที่เกิดแทบทุกวัน = ตัวเลขไม่สมเหตุสมผล
                       แปลว่าการแก้ส่วนใหญ่ไม่ได้วิ่งผ่านทางที่มี log
เกิดตอนไหนของวัน      : ระหว่างวัน
ใครทำให้เลขขยับ       : กิ๊ฟ (⚠️ ไม่ใช่ความผิดกิ๊ฟ ระบบไม่มีช่องให้ทำอย่างอื่น)
```

**📍 ไล่ S062 ย้อนหลังตามที่ PM สั่ง เลขเดินแบบนี้ (เวลา UTC · +7 = ไทย)**
```
06 ก.ย. 06:21   ปิดวันอัตโนมัติ -> 0        actor: MoKHAUNG   (ระบบทำ แต่ลงชื่อคน)
07 ก.ย. 10:31-32 แก้จำนวน x4 -> ยัง 0       กรอก 4 ครั้งติดกัน เลขไม่ขยับ
07 ก.ย. 10:32   เติมสต็อค +4 -> 4
07 ก.ย. 10:33   แก้จำนวน +1 -> 5
08 ก.ย. 02:02   ปิดวันอัตโนมัติ -> 0        actor: ระบบ       5 ที่เพิ่งใส่ หายทั้งก้อน
08 ก.ย. 10:28   แก้จำนวน -> ยัง 0
10 ก.ย. 03:16   แก้จำนวน -> 0
10 ก.ย. 03:20   แก้จำนวน -> 0
10 ก.ย. 03:48   เติมสต็อค +3 -> 3          "ทำเพิ่ม 3" ที่นัทพูดถึง (จริงๆ คือของเหลือ)
10 ก.ย. 03:48   แก้จำนวน -> 2
10 ก.ย. 03:49   เติมสต็อค +1 -> 3
```
**ข้อสังเกตจากเส้นนี้ 2 อย่าง**
· 7 ก.ย. โม๋ข่องกด "แก้จำนวน" **4 ครั้งใน 1 นาที** แล้วเลขไม่ขยับ จนต้องเปลี่ยนไปกด "เติมสต็อค" ถึงติด
  **หน้าจอไม่ได้บอกว่ากดผิดช่อง คนเลยกดซ้ำจนกว่าจะเดาถูก** แพทเทิร์นเดียวกันซ้ำอีกที 10 ก.ย. 03:16-03:48
· **สิ่งที่ครัวใส่ไว้ 5 เมื่อ 7 ก.ย. ถูกล้างเป็น 0 ในเช้าวันถัดมา**
  ตรงกับที่นัทถามว่า "ครัวลงตงไหนว่าได้ 5" -> **เลข 5 นั้นมีอยู่จริง และหายจริงเพราะปิดวันอัตโนมัติ ไม่ใช่ครัวจำผิด**

**📍 "สั่งแล้ว 4" บนจอ กับออเดอร์จริงในระบบ ไม่ตรงกัน**
ออเดอร์ที่มี S062 และส่งวันนี้ (10 ก.ย.) ในฐานข้อมูล = **U-0910-003 จำนวน 3 กล่อง ใบเดียว**
แต่หน้าจอครัวขึ้น "สั่งแล้ว 4 · รูปหน้าคน 4" -> **มีอีก 1 ที่มาจากที่อื่น**
(ใบที่ยกเลิก U-0908-006 หรือการสลับเมนูที่ไม่มี log)
-> ช่องว่าง 1 ชิ้นนี้ คือชิ้นเดียวกับที่ตู้เย็นนับได้ 3 แต่จอบอก 4
**ต่างกัน 1 ทั้งสองฝั่ง = เป็นเรื่องเดียวกัน ไม่ใช่คนละเรื่อง**

**แย้ง/เสริมห้องอื่น:**

· **แย้งกรอบคำถามข้อ 3 ของ PM** โจทย์เขียนว่า "ไล่ให้ครบว่ามีกี่ทางที่เลขขยับได้"
  **ไล่ครบไม่ได้ด้วยข้อมูลที่มี** เพราะ 2 ทางที่ใหญ่ที่สุด (ลูกค้าสั่ง / แก้จากหลังบ้าน) แทบไม่ทิ้ง log
  คำตอบที่ซื่อสัตย์คือ **"รู้ว่ามีอย่างน้อย 5 ทาง และรู้ว่า 2 ทางในนั้นตามไม่ได้เลย"**
  ถ้าตอบว่าไล่ครบแล้ว = โกหกตัวเอง แล้วจะไปออกแบบทางแก้บนข้อมูลที่ไม่ครบ

· **เสริมเรื่องที่นัทห่วงว่า "ใส่ทำเพิ่ม 3 ทั้งที่ไม่ได้ทำเพิ่ม จะพังตามมาไหม" พังจริง 2 ทาง**
  1. ยอดผลิตสะสมจะเกินจริง ใครเอา "ทำเพิ่ม" ไปคำนวณกำลังผลิต/ต้นทุนวัตถุดิบ จะได้เลขเฟ้อ
  2. **ห้อง 05 ใช้ยอดขายย้อนหลังคำนวณสต๊อกรายสัปดาห์ที่ส่งครัว** ถ้าฐานเฟ้อ เลขที่ส่งครัวก็เฟ้อตาม
  **ตอนนี้ยังไม่พัง เพราะ 05 คำนวณจาก order_items (ของที่ขายจริง) ไม่ได้ใช้ช่อง "ทำเพิ่ม"**
  แต่ถ้าใครเผลอเปลี่ยนไปใช้ช่องนั้นเมื่อไหร่ = เฟ้อทันที

· **ขอบเขตที่ผมไม่แตะ** ไม่พูดเรื่องควรวางแผนผลิตยังไง (ISSUE 01) และไม่เสนอหน้าจอใหม่ ตามที่นัทล็อกไว้
