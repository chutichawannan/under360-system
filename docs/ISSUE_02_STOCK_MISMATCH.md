## 📸 หน้าจอที่ครัวเห็นเช้านี้ (10 ก.ย.) — ของจริง

```
S062 · S2 · W37   ข้าวคั่วกลิ้งอกไก่แครนเบอร์รี่ไข่ต้ม
มีจริง 4  +  กำลังเติม 0  –  สั่งแล้ว 4      →  ขายได้ 0

## 🧩 ปัญหาที่นัทไล่มา — **คำต่อคำ ห้ามตีความ ห้ามย่อ**

### ① เลขบนจอกับของในตู้ไม่ตรง
> *"ปัญหาของ S2 และทุกรายการ เกิดขึ้นที่ในระบบของมือถือพนักงานครัว เห็นตอนนี้ว่า**มีจริงทั้งหมด 4 แต่นับในตู้เย็นตอนนี้ดันมี 3**"*

### ② ของ 4 ชิ้นนั้น "ถูกจัดไปแล้ว" — แล้ว 3 ที่เหลือคือของใคร
> *"ไม่ใช่แค่นี้ เพราะว่า**มีจริง 4 และมีรูปหน้าคนทั้งหมด 4** แปลว่านอกจากมีจริงแล้ว รายการนี้**ถูกจัดไปเรียบร้อยแล้ว** ดังนั้นทั้ง 4 รายการนี้ควรจะอยู่ในถุงอาหารที่ถูกแพ็คไว้แล้ว และ**เราไม่รู้ว่าถูกส่งไปหรือยัง หรือยังอยู่ในครัว** และ 3 รายการที่ยังเหลืออยู่ในตู้เย็น **มันควรจะเป็นของ 4 คนนั้น หรือว่ามันเป็นของที่เหลือขึ้นมาจริงๆ**"*

### ③ จะเพิ่มของที่เหลือกลับเข้าระบบยังไง — ตอนนี้ใช้ช่องผิดความหมายอยู่
> *"ปัญหาที่ตามมาก็คือ**เราจะเพิ่มสต๊อกยังไง ช่องไหนดี** ตอนนี้แก้ปัญหาเบื้องต้นโดยการให้โม๋ข่องแจ้งลงไปในระบบว่า**ทำเพิ่ม 3** ซึ่งจริงๆ **เราไม่ได้ทำเพิ่มขึ้นมา 3 หรอก แต่เรามีเหลือ 3** เราเลยใส่เติมเข้าไปว่าทำเพิ่ม 3 ซึ่งเราก็ไม่รู้ว่าจะมีปัญหาตามมาไหม"*

### ④ 3 ที่เหลือ อาจเป็นของที่ยังไม่ได้จัด — แต่ก็ไม่ควรมีของเหลือตอนเช้า
> *"เช่น เอ้ย จริงๆ 3 อันนี้**ควรจะถูกจัดให้ลูกค้าแต่ว่ายังไม่ได้จัด** ซึ่งอันนี้ก็มีความเป็นไปได้ และก็มีความเป็นไปไม่ได้เช่นกัน เพราะว่า**ทุกๆ วันควรจัดของตอนจบวัน** ซึ่งตอนนี้มันเป็น**เริ่มต้นเช้าวันใหม่ ไม่ควรมีของเหลือ 3**"*

### ⑤ ไม่รู้ว่าลูกค้าสั่งตอนไหน สต๊อกถูกตัดเมื่อไหร่
> *"ยังจะมีปัญหาแทรกซ้อนอีกเยอะมาก **ไม่รู้ลูกค้าสั่งตอนไหน ถูกตัดสต๊อกไปเมื่อไหร่** บางทีก็อาจจะมีเหตุการณ์เช่น มีจริง 3 ลูกค้ากดสั่งมาตอนกลางคืนที่ครัวเลิกงาน ก็อาจจะกลายเป็นมีจริง 4 ที่ถูกจัดเข้าไป ทำให้สต๊อกเป็นศูนย์ อันนี้ก็คิดมั่วไปหมด"*

### ⑥ งานจัดของระหว่างวันของกิ๊ฟ
> *"ระหว่างวันกิ๊ฟสั่งให้ครัวจัดของให้ลูกค้า ซึ่งก็ต้องมาดูกันอีกว่า**จัดจากรายการที่ถูกหักสต๊อกไว้แล้ว หรือว่ามีลูกค้ามาสั่งด่วน**"*

## 🗝️ คำตอบจากกิ๊ฟ (แอดมิน) — **นัทถามเองแล้ว · หลักฐานชั้นต้นที่สำคัญที่สุดของ issue นี้**

> *"มีค่ะแต่ไม่บ่อย ส่วนมาก**ที่สต๊อกไม่ตรงเพราะ order ลูกค้าบางคนขาด ก็จะให้ลูกค้าเลือกเมนูใหม่ทดแทน** อาจจะเป็นส่วนที่ทำให้สต๊อกไม่ตรง · **กรณีการตัดสต๊อกของหนูคือตัดแมนนวล โดยเข้าหลังบ้านแล้วลบเอาเลยค่ะ**"*

🔴 **อ่านให้ดี:** มีการเปลี่ยนสต๊อกที่**ไม่ได้ผ่านทางที่ระบบออกแบบไว้** และ**ไม่ได้ผ่านหน้าครัว** — ทุกห้องต้องไล่ว่าการ "ลบเอาเลยที่หลังบ้าน" ไปโผล่/ไม่โผล่ที่ไหนบ้าง

⚠️ **ห้ามตีความว่ากิ๊ฟทำผิด** — กิ๊ฟทำเพราะไม่มีทางอื่นให้ทำ **ที่ผิดคือระบบไม่มีช่องให้** (กฎบ้านนี้: ระบบที่บังคับให้คนเลี่ยง = ระบบออกแบบพลาด)

### 🎯 สิ่งที่ต้องตอบให้ได้ก่อนจบประชุม
1. **เลข "มีจริง" หมายความว่าอะไรกันแน่** — ของในตู้ ? ของที่ทำเสร็จวันนี้ ? ของที่ยังไม่ถูกจอง ?
2. **"สั่งแล้ว 4" + "รูปหน้าคน 4" หักออกจาก "มีจริง" ไปแล้วหรือยัง** หรือหักซ้ำ/ไม่หักเลย
3. **มีกี่ทางที่เลขนี้ขยับได้** — ลูกค้ากดสั่ง · ครัวกรอก · ปิดวันอัตโนมัติ · กิ๊ฟลบที่หลังบ้าน · อื่นๆ **ไล่ให้ครบทุกทาง**
4. **ทางไหนบ้างที่ขยับแล้วไม่มี log** = จุดที่ตามไม่เจอตลอดกาล
5. **ของเหลือจริงตอนเช้า ควรลงช่องไหน** ("ทำเพิ่ม" ที่ใช้อยู่ตอนนี้ ทำให้อะไรพังตามมาบ้าง)

### ✅ ตอบ 5 คำถามที่ต้องได้ก่อนจบประชุม (ตอบจากโค้ด ไม่ใช่ความเห็น)

**1. "มีจริง" แปลว่าอะไรกันแน่** → **ไม่ใช่ทั้ง 3 อย่างที่ถามมา** · มันคือ *ผลลบทางบัญชี* = (ขายได้อีก) + (ออเดอร์ที่ยังไม่ถูกกดจัดของ) − (กำลังเติม) · **ไม่มีใครเคยนับมันไว้ที่ไหน** และค่าที่ครัวนับด้วยตาจริงๆ ถูกเก็บแยกในคอลัมน์ `actual_stock` ที่**หน้าครัวไม่ได้เอามาแสดง** (`kitchen_queue.html:1462` เขียนเหตุผลไว้ตรงๆ) — ตอนนี้ 2 ค่านี้ไม่ตรงกันอยู่จริง (3 vs 4)

**2. "สั่งแล้ว 4" หักออกจาก "มีจริง" แล้วหรือยัง** → **หักไปแล้วครั้งหนึ่ง แล้วถูกบวกกลับ** · ตอนลูกค้ากดสั่ง `adjust_stock` หัก "ขายได้อีก" ทันที · แล้วบรรทัด 1467 บวก "สั่งแล้ว" กลับเข้าไป (ตั้งใจ — เพื่อให้ "ของในตู้" ไม่ลดตอนลูกค้าสั่ง แต่ลดตอนครัวจัดของ ตามที่นัทสั่ง) → **ไม่ได้หักซ้ำ และไม่ได้ไม่หัก** แต่ผลคือ *ของที่ขายไปแล้วยังถูกนับว่าอยู่ในตู้* จนกว่าจะมีคนกดปุ่ม — ซึ่งตามข้อ 2 ไม่มีใครกดมา 10 วัน
· ส่วน **"รูปหน้าคน 👥" ไม่ได้แปลว่าจัดของแล้ว** — มันคือปุ่มกดดูรายชื่อคนสั่ง (`kitchen_queue.html:1492`) มีไอคอนเดียวเสมอ ไม่ว่าจะกี่คน · **นัทอ่านหน้าจอตามที่หน้าจอสื่อ แล้วหน้าจอสื่อผิด**

เสริมให้ครบ: **มันไม่ใช่งานตั้งเวลา** ไม่มีใน `vercel.json` เลย · `kitchen_queue.html:1329` สั่งให้รันตอนหน้าสต็อกถูกเปิดครั้งแรกของวัน → **09:02 คือนาทีที่มีคนเปิดหน้าครัว ไม่ใช่เวลาที่ระบบตั้งไว้** · ผลตามมา: วันไหนไม่มีใครเปิดหน้าครัว ของก็ไม่ถูกปิดวัน แล้วค้าง "กำลังเติม" ขายล่วงหน้าต่อไปเรื่อยๆ

**🟢 เสริมเลขา ข้อ 4 — "แก้ไปมา 5 ครั้งใน 33 นาที"**
ไม่ใช่ความสับสนของคนกรอกอย่างเดียว — **ผมเจอเหตุผลเชิงกลไกแล้ว (ข้อ 1 ของผม)**: โม๋ข่องพิมพ์ 3 แล้วเลขเด้งกลับเป็น 4 · พิมพ์ 0 ก็เด้งกลับเป็น 4 · **ไม่ว่าพิมพ์อะไรก็ไม่มีทางได้ 3** สุดท้ายจึงหันไปใช้ช่อง "กำลังเติม" แทน = คนทำถูกทุกขั้นตอน ระบบไม่ยอมรับความจริงเอง

**🔴 แย้ง 05 ข้อ ① — "มี 3 ช่อง แต่ละหน้าจออ่านคนละช่อง"**
เจอคอลัมน์ถูก แต่สรุปผิดครึ่งหลัง — **`stock_reserved` ไม่มีโค้ดที่ไหนเขียนมันเลยสักบรรทัดทั้ง repo** · ถูกอ่านแค่ 2 บรรทัด (`operation_hub.html:2846-2847`) เพื่อโชว์ป้าย "จอง N / พร้อม" ในรายการเมนูฝั่งแอดมิน
→ มันไม่ใช่ "ช่องที่ 3 ที่ทำให้เลขไม่ตรง" แต่เป็น **ค่าค้างจากยุคก่อนที่ตายไปแล้ว แต่ยังโชว์ป้ายหลอกแอดมินอยู่**: ตอนนี้ 52/130 เมนูเปิดขายมีค่านี้ค้าง เช่น **BB01 = "จอง 132" · BB02 = "จอง 124" · A18 = "จอง 108"** ทั้งที่ไม่เคยมีใครจองขนาดนั้น

⚠️ แต่ **ข้อสังเกตของ 05 ยังมีค่า** ในอีกความหมาย: หน้าจอแอดมินกำลังบอกกิ๊ฟว่า "จอง 132" จากตัวเลขที่ไม่มีใครดูแล = อีกจอที่โกหกเงียบๆ

**🔴 แย้ง 05 ข้อ ④ (ซ้ำกับเลขา ข้อ 5) — "ใบยกเลิกไม่คืนของ"**
เหตุผลเดียวกับที่แย้งเลขาไว้ข้างบน: **โค้ดคืนจริง** (`operation_hub.html:1724`) · การไม่เจอคำว่า "คืน" ในประวัติสต็อก **ไม่ได้แปลว่าไม่ได้คืน** — แปลว่าการคืนไม่ถูกบันทึก · 2 ห้องสรุปตรงกันจากหลักฐานชิ้นเดียวกัน (log ว่าง) แต่หลักฐานชิ้นนั้นพิสูจน์ข้อสรุปนี้ไม่ได้
📌 **นี่คือกับดักที่บ้านนี้โดนซ้ำ: "ไม่มี log" ≠ "ไม่เกิดขึ้น"** — ต้องเปิดโค้ดดูก่อนทุกครั้ง

**🟢 เสริม 05 ข้อ ③ — "ปิดวันอัตโนมัติถูกบันทึกในชื่อคน 26/64 ครั้ง"**

→ **ผลกระทบตรงกับที่ 05 เตือน**: โม๋ข่องเฝ้า 3 วันแล้วเปิด log จะเห็นชื่อตัวเองบนเหตุการณ์ที่ระบบทำ

**กติกาที่ยึด: ไม่มีประโยคยาว · ทุกบรรทัดอ่านออกด้วยเลข+รหัสสั้น+รูป · ครัวที่อ่านไทยไม่ได้ 4/6 คนต้องใช้งานได้**

**เช้า — ใบตกค้างเมื่อคืน**
```
🌙 ตกค้าง 2 ใบ

S2  ×3   [รูปเมนู]
D1  ×1   [รูปเมนู]
```
**ด่วน — แอดมินสั่งระหว่างวัน**
```
⚡ ด่วน

S5  ×2   [รูปเมนู]
```
**เปลี่ยนเมนูให้ลูกค้า**
```
🔁 เปลี่ยน

S2  ×1   ❌  [รูป]
S5  ×1   ✅  [รูป]
```

**🔑 จุดที่แก้ปัญหา "รูปตอบไม่ได้ว่าใบไหน" ที่ผมค้านเลขาไว้รอบ 3 — แก้ได้ด้วยการตอบกลับในข้อความนั้น**
ครัวถ่ายรูปถุงแล้ว **ตอบกลับ (reply) ที่ข้อความใบนั้นโดยตรง** ไม่ใช่ส่งลอยเข้ากลุ่ม
→ ระบบรู้ทันทีว่ารูปนี้เป็นของใบไหน **เพราะไลน์ส่งเลขข้อความต้นทางมาให้ในตัว**
→ **ครัวไม่ต้องพิมพ์เลขใบ ไม่ต้องอ่านหนังสือ แค่กดค้างที่ข้อความแล้วตอบกลับ**
→ **ผมถอนคำค้านรอบ 3 บางส่วน** — รูปใช้เป็นสัญญาณจัดได้จริง **ถ้าเป็นการตอบกลับ** · ที่ยังค้านคือรูปส่งลอย
```
ใครลงมือ            : 05 (โครงข้อความ + ฝั่งอ่าน reply)  ·  เลขา+กะปัน (ท่อยิงเข้ากลุ่ม)
เทสยังไงถึงรู้ว่าได้ผล : ยิงเข้าห้องทดสอบ 3 ใบ แล้วตอบกลับ 1 ใบด้วยรูป
                      -> ระบบต้องขึ้นว่าใบนั้นจัดแล้ว **อีก 2 ใบต้องยังไม่จัด**
                      แล้วให้โม๋ข่องลองตอบกลับเอง 1 ครั้ง โดยไม่มีใครสอน — ทำได้ = ผ่าน
ถ้าพังอีกจะรู้ได้ยังไง : เช้าไหนข้อความไม่ออก หรือ reply เข้ามาแล้วสถานะไม่เปลี่ยน = แจ้งกลับห้อง 05 เอง
```

### 🅲 หน้า C — แอดมินสั่งจัดของด่วน

**เกณฑ์ตัดสินที่ PM ตั้งไว้: ถ้ากิ๊ฟยังอยากลบหลังบ้านเองอยู่ = ออกแบบพลาด**
→ ทุกอย่างข้างล่างนี้ออกแบบให้ **จังหวะน้อยกว่า** วิธีที่กิ๊ฟใช้อยู่ทุกวันนี้

**แอดมินกดอะไร กี่จังหวะ**
```
จังหวะที่ 1  เปิดใบที่มีอยู่แล้วในระบบ  (ห้ามสั่งลอย — ไม่มีใบ = ไม่มีปุ่มนี้)
จังหวะที่ 2  แตะ "⚡ ด่วน"              จบ
```
· ระบบกันของให้อัตโนมัติ · ยิงเข้ากลุ่มไลน์ครัวทันที · การ์ดเด้งขึ้นบนสุดของแถว "ต้องจัดตอนนี้"
· **แอดมินไม่ต้องแตะตัวเลขสต๊อกเลยสักครั้ง** — นี่คือจุดที่แทนที่การ "ลบเลขที่หลังบ้าน"

**ครัวรู้ได้ยังไง — ครัวไม่ได้จ้องจอทั้งวัน**
· **ไลน์เป็นตัวปลุก จอเป็นที่ทำงาน** · ของด่วนต้องมาทางไลน์เสมอ เพราะครัวเปิดไลน์อยู่แล้วทั้งวัน
· ของด่วน = ข้อความแยกใบ ไม่รวมกับสรุปเช้า (รวมแล้วจะจมหาย)

**ของด่วนไปแทรกตรงไหน ไม่ให้กลบงานเดิม**
· อยู่ **บนสุดของแถว "ต้องจัดตอนนี้"** ที่เลขาออกแบบไว้ · ใช้ ⚡ + ขอบสีต่างจากใบตกค้างเมื่อคืน (ขอบแดง)
· **ไม่สร้างแถวใหม่ ไม่สร้างหน้าใหม่** — กติกา "ครัวหน้าเดียว" ที่เลขาตั้งไว้ ผมเห็นด้วยเต็มที่
· ใบด่วนที่จัดเสร็จแล้วต้องหายออกจากแถวทันที ไม่งั้นแถวนี้จะกลายเป็นกองที่ไม่มีใครเชื่อ

**เคส "ลูกค้าได้ของขาด เลยให้เลือกเมนูใหม่แทน" — ต้องจบใน 2 จังหวะ**
```
จังหวะที่ 1  ในใบนั้น แตะเมนูเดิม -> เลือกเมนูใหม่
จังหวะที่ 2  ยืนยัน                จบ
```
**สต๊อกขยับเองทั้ง 2 ตัว ในการกดครั้งเดียว:**
· เมนูเดิม  → คืนของกลับ +1  (วันนี้ไม่มีการคืนเลยสักครั้งทั้งเดือน = ของหายจากระบบทุกครั้งที่สลับ)
· เมนูใหม่  → กันของ −1
· ทั้งคู่ทิ้งรอยว่าใครสลับ ตอนไหน เพราะใบไหน · ครัวได้ข้อความ 🔁 เปลี่ยน ตามโครงด้านบน

```
ใครลงมือ            : u-maintainer (ฝั่งปุ่ม+สต๊อก)  ·  05 (ฝั่งข้อความเข้าไลน์)
เทสยังไงถึงรู้ว่าได้ผล : ให้กิ๊ฟทำงานจริง 1 เคสด้วยปุ่มใหม่ แล้ว **นับจำนวนจังหวะเทียบกับวิธีเดิมของกิ๊ฟ**
                      มากกว่าเดิม = ตก · และเช็คว่าเมนูเดิมได้ของคืนจริง เมนูใหม่ถูกกันจริง ในการกดครั้งเดียว
                      **05 ขอเป็นห้องตรวจซ้ำ**
ถ้าพังอีกจะรู้ได้ยังไง : ตัวเฝ้ารายวันนับ "การแก้สต๊อกที่ไม่ผูกกับใบไหนเลย" — ปกติต้องเป็น 0
                      ไม่ใช่ 0 = ยังมีคนต้องเลี่ยงไปแก้มือ แปลว่าปุ่มยังใช้ไม่ได้จริง
```

                      ไม่ใช่เช้าวันรุ่งขึ้น

```
ชั้นที่ 1  ดูผิดช่อง
          actual_stock = 0     <- ช่องที่ครัวกรอก  (u กับ 05 ไปอ่านช่องนี้)

          => หน้าจอไม่มีอะไรแยก 2 อย่างนี้ให้เลย
```

**ทำไมเคสนี้สำคัญกว่าตัวมันเอง**
· **คนดูแลโค้ดเอง (u) กับคนยิงบรอดแคสต์ (05) อ่านคนละช่องกัน ในวันเดียวกัน แล้วสรุปตรงกันว่า "ของไม่มี" ทั้งที่ของขายได้ปกติ**
· ถ้า 2 ห้องที่เปิดโค้ดและ query DB เองได้ยังพลาด **ครัวกับแอดมินไม่มีทางไม่พลาด**
· และผลที่เกือบเกิด: ห้อง 05 เกือบสั่งครัวให้**ผลิตเพิ่มโดยไม่จำเป็น** จากการอ่านเลขผิดช่อง

**เพิ่มเข้าข้อสรุปของที่ประชุม 1 บรรทัด**

**เย็น (จุดตัดรอบ = ค่าคงที่ค่าเดียวในระบบ):** ครัวจัดทุกใบที่เข้าก่อนตัดรอบ (รวมใบล่วงหน้า — กติกาที่อยู่ในหัวนัท ถูกเขียนออกมา) → จัดเสร็จให้ "สัญญาณจัดแล้ว" 1 จังหวะ/ใบ (แตะการ์ดแบบ 05 หรือรูปถุงแบบที่ครัวถ่ายอยู่แล้ว — รับได้ทั้งคู่ เข้าจุดเก็บเดียวกัน) → ปิดท้ายวัน ครัวนับตู้ 1 ครั้ง รายงาน "ของเหลือ" (ช่องความหมายเดียว — เห็นด้วยกับ 05 ว่าห้ามใช้ช่อง "ทำเพิ่ม")

**D (ขึ้นแบบไหนไม่งง):** ครัวเห็น **เลขเดียวต่อเมนู = "ตอนนี้ต้องมีในตู้กี่กล่อง"** — เลขจอง/ขายได้/กำลังเติม เป็นเรื่องหลังบ้าน ไม่โชว์ครัว

### ส่วนที่ 2 — แมคคานิกที่ผมเสนอ ครบทั้งวง

> **หลักเดียวที่คุมทั้งวง:** ระบบต้องนับ **"ของ"** ไม่ใช่ **"เลข"**
> มีเลข **3 ตัว แต่ละตัวมีเจ้าของคนเดียว และไม่มีตัวไหนถูกคำนวณมาจากอีกตัว**
> ```
> ของในตู้     — เจ้าของ = ครัว    ขยับเมื่อ "ของถูกยก" เท่านั้น (ทำเสร็จ / หยิบลงถุง / นับใหม่)
> จองแล้ว      — เจ้าของ = ออเดอร์  ขยับเมื่อใบเปลี่ยน (สั่ง / ยกเลิก / แอดมินแก้รายการ)
> กำลังทำ      — เจ้าของ = ครัว    ขยับเมื่อครัวบอกว่าจะทำ และเมื่อครัวบอกว่าทำเสร็จ
>
> ลูกค้าซื้อได้ = ของในตู้ + กำลังทำ − จองแล้ว     ← ตัวเดียวที่คำนวณ และ "ห้ามมีใครกรอกมัน"
> ```
> วันนี้ทำกลับด้าน: เก็บ "ลูกค้าซื้อได้" แล้วคำนวณย้อนหา "ของในตู้" — **นี่คือจุดเดียวที่ต้องพลิก ที่เหลือตามมาเอง**

**ตอบคำถามนัททั้ง 4 ข้อ ตามช่วงของวง:**

#### 🅑 ① ลูกค้าสั่ง — "แมคคานิกตอนลูกค้าสั่งเข้ามาควรเป็นแบบไหน"
```
แมคคานิก           : ประตูรับออเดอร์ทุกบานใช้เวลาปิดรับ "ค่าเดียวกัน" และตัดวันให้เองทั้ง 2 บาน
                    · ลูกค้ากดเอง และแอดมินสั่งแทน ต้องได้ปฏิทินหน้าตาเดียวกันเป๊ะ ณ วินาทีเดียวกัน
                    · เวลาปิดรับต้องเป็น "เวลาคงที่" ไม่ใช่ผูกกับเวลาที่ครัวเลิกงานจริงของวันนั้น
ใครลงมือ            : ห้อง u (2 ไฟล์) · เลขเวลา = ห้องครัวตอบ ไม่ใช่ห้อง u ตั้ง
เทสยังไงถึงรู้ว่าได้ผล : เดินเคสจริงซ้ำ U-0910-003 (เปิด 20:00 · ส่ง 10 ก.ย.) → หลังคัทออฟ
                    **ฟอร์มสั่งแทนลูกค้าต้องกดวันพรุ่งนี้ไม่ได้** และ LIFF ต้องตัดวันเดียวกันเป๊ะ
ถ้าพังอีกจะรู้ได้ยังไง : ตัวตรวจรายวัน "ใบที่เปิดหลังคัทออฟ แต่วันส่งเร็วกว่าที่กติกาอนุญาต" → ต้อง = 0 ทุกวัน
```

#### 🅑 ② ระบบรับ/ตัดของ — **สั่ง = "จอง" ไม่ใช่ "เอาของออกจากตู้"**
```
แมคคานิก           : ลูกค้าสั่ง → ของถูก "จอง" ไว้ · ของยังอยู่ในตู้จนกว่าจะถูกหยิบลงถุงจริงที่ช่วง ④
                    ทุกทางที่ทำให้ใบเปลี่ยน ต้องขยับ "จอง" ทางเดียวกันหมด — รวม
                    **ปุ่มเพิ่ม/แก้/ลบรายการในใบ ซึ่งวันนี้ไม่ขยับอะไรเลยสักตัว**
ใครลงมือ            : ห้อง u
เทสยังไงถึงรู้ว่าได้ผล : เปิดใบทดสอบ → เพิ่มเมนู A 2 กล่องผ่านปุ่มแอดมิน → "จอง" ของ A ต้อง +2 และ
                    "ลูกค้าซื้อได้" ต้อง −2 ทันที · ลบออก → ต้องคืนครบทั้ง 2 ค่า · **"ของในตู้" ต้องไม่ขยับเลย**
                    (วันนี้ทำแล้วไม่มีค่าไหนขยับเลย แต่ "มีจริง" บนจอครัวขยับ)
ถ้าพังอีกจะรู้ได้ยังไง : ตัวตรวจรายวันเทียบ "ผลรวมจองในใบที่ยังไม่ถูกจัด" กับ "ยอดจองในตาราง"
                    ต่างกันเมื่อไหร่ = มีทางที่แก้ใบโดยไม่ขยับจอง
```

## 1️⃣ รากเดียวของทุกอาการ — และมันกลับด้านอยู่

**วันนี้ระบบเก็บ "ลูกค้าซื้อได้อีกกี่กล่อง" เป็นความจริง แล้วคำนวณย้อนกลับว่าในตู้มีเท่าไหร่**
```

```
ผลของการกลับด้าน: **ตัวแปรไหนเพี้ยน เลขในตู้เพี้ยนตาม โดยไม่มีใครแตะของสักกล่อง**

### 3 เลข — แต่ละตัวมีเจ้าของคนเดียว และไม่มีตัวไหนคำนวณมาจากอีกตัว
| เลข | เจ้าของ | ขยับเมื่อ |
|---|---|---|

```

│  [ วันนี้ ▾ ]              👤 โม๋ข่อง        │  ← แถวเดียว: วัน + ใครกำลังใช้

│   ต้องส่งวันนี้    24 กล่อง  ·  9 ใบ        │  ← เลขใหญ่สุดในหน้า ไม่ต้องอ่านอะไรก็รู้ว่างานเท่าไหร่
│   จัดแล้ว  ███████░░░  17/24               │  ← แถบยาว ไม่ใช่ประโยค
├────────────────────────────────────────────┤

└────────────────────────────────────────────┘
```

**โหมด 📦 จัดของ** (ค่าเริ่มต้นตลอดวัน) — เหมือนหน้าที่โม๋ข่องใช้อยู่แล้ว แต่ตัดของที่ไม่ใช้ออก
```
1 ใบ = 1 การ์ด · เรียงตามรอบส่ง
   ┌ ชื่อลูกค้า                       ☑ 3/5 ┐
   │  [รูป]  S2   ×2      ⬜             │   ← รหัสสั้น + รูป + จำนวน · แตะแถวไหน = ติ๊กแถวนั้น
   │  [รูป]  D1   ×1      ✅             │
   └────────────────────────────────────┘
ติ๊กครบทุกแถว → การ์ดพับเองเป็นสีเขียว ไม่ต้องกดปุ่มยืนยันอะไรอีก
```

**โหมด 🔢 นับของ** (เช้า + ก่อนเลิกงาน) — **ครัวนับอย่างเดียว ไม่มีอะไรให้หักลบ**
```
   [รูป]  S2  ข้าวคั่วกลิ้ง        [   3   ]     ← ช่องเดียว เลขใหญ่ แตะแล้วพิมพ์ทับได้เสมอ
                                   ⚠️ ระบบคิดว่า 4
   [รูป]  D1  ...                  [   6   ]     ← ตรงกัน = ไม่มีป้ายอะไรเลย
```
· **ช่องนับมีช่องเดียว** — ไม่มี "ของจริง/กำลังเติม/ขายได้" ให้เลือกใส่ผิดช่องอีก
· ระบบคิดไม่ตรงกับที่นับ → ขึ้น **⚠️ + ตัวเลข** เฉยๆ · **ไม่บล็อก ไม่เด้งกลับ ไม่ถามเหตุผล** · เลขที่ครัวพิมพ์ชนะเสมอ
· ส่วนต่างถูกเก็บเงียบๆ ไว้ให้ระบบไล่หาทางรั่วทีหลัง — **ครัวไม่ต้องรับรู้ ไม่ต้องอธิบาย**

**หน้า A · แตะอะไรได้ — กี่จังหวะจบ 1 งาน**
| งาน | จำนวนจังหวะ | วันนี้ใช้กี่จังหวะ |
|---|---|---|
| จัดของ 1 กล่อง | **แตะ 1 ครั้ง** (ติ๊กแถว) | แตะ 1 + ต้องกดปุ่มยืนยันอีก 1 (และคนส่วนใหญ่ไม่รู้ว่ามี) |
| นับของ 1 เมนู | **แตะ 1 + พิมพ์เลข** | แตะดินสอ → เลือกช่อง (2 ช่อง) → พิมพ์ → กดบันทึก → **เลขเด้งกลับ → ทำใหม่** |
| ดูว่าเหลืองานเท่าไหร่ | **ไม่ต้องแตะ** (อยู่บนหัวตลอด) | ต้องสลับแท็บไปนับเอง |
