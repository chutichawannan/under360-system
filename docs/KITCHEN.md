## 🌱 จุดกำเนิดโปรเจค — มาจากครัวนี่แหละ

โปรเจค Under360 System **เริ่มจากปัญหาครัวล้วนๆ**: ครัวโทรมาถามนัทว่า *"สูตรอาหารนี้ทำยังไงนะ หายไปแล้ว"*
จุดเริ่มต้นแค่นั้น → ลากยาวมาเป็นระบบทั้งหมดที่มีตอนนี้ (DB สูตร → เมนู → ออเดอร์ → LIFF → agents)

**นัยยะ:** ครัว = ต้นทางของโปรเจค แต่กลับเป็นเสาที่ได้เครื่องมือน้อยสุด (เสา 2 "ปฏิบัติการ & ต้นทุน" = 20%)
เพราะนัทอยู่ต่างประเทศ/ไม่ได้เข้าครัวเอง → **ปัญหาหลายอย่างครัวทำไม่ได้เพราะไม่มีคนอยู่หน้างาน**

## 👑 โครงสร้างอำนาจ — นัท = หัวหน้าครัวตัวจริง

**นัทยืนยันเอง 5 ส.ค.:** *"ฉันเนี่ยแหละคือหัวหน้าครัวที่แท้จริง พนักงานทุกคนทำตามคำสั่งฉันหมด"*

→ **กฎ:** คำถามเชิงกติกาการผลิต (ทำได้/ไม่ได้ · เวลา · กำลังผลิต) → **ถามนัทจบในตัว ไม่ต้องไปสำรวจครัวก่อน**
→ อ่อง = หัวหน้าแม่ครัวเชิงปฏิบัติ (คุมมือ) **ไม่ใช่คนเคาะกติกา**

## 👥 ทีมครัว 6 คน — ทุกคนเป็นแรงงานต่างด้าว (ไทใหญ่)

| ชื่อ | อ่านไทย | บทบาทจริง | จุดแข็ง / ข้อสังเกต |
|---|---|---|---|
| **อู** | ✅ | **หัวหลักจัดออเดอร์** — อยู่ครัวห้องใน ล้อมรอบด้วยตู้ฟรีซ 5+ ตู้ + ตู้แช่ 1 · รับโทรศัพท์แพลตฟอร์ม (Grab/LINE MAN/Robinhood) · ดูอาหารเด็ก · **เช็คสต็อค** | ศูนย์กลางข้อมูลของครัว — ถ้าจะต่อ chatbot/tools เข้าครัว อูคือ node แรก |
| **โม๋ข่อง** | ✅ | คุยกับคนไทย ช่วยอูรับสายแพลตฟอร์ม · ส่งของให้ไรเดอร์หน้าบ้าน · ทวงของโกโฮลเซลว่ามาส่งยัง | ไม่ค่อยฉลาดเท่าไหร่ แต่**อ่านไทยได้** เลยได้งานสื่อสารไปโดยปริยาย |
| **โว๊** | ❌ | แม่ครัว | 🔑 **ฉลาด ขยัน เก็บรายละเอียด ขี้เกรงใจ** — นัทประเมิน: **ถ้าอ่านไทยได้ + มี tools ดีๆ = ที่ 1 ในครัว** → **เป้าหมายอันดับ 1 ของ tools ภาษา (ROI สูงสุด)** |
| **อ่อง** | ❌ | **หัวหน้าแม่ครัว** | เร็วมาก งานครัวเสร็จเร็วเสมอ ขาดไม่ได้ · ⚠️ **เร็วจนหลายครั้งไม่ทำตามสูตร** → ต้องหา "ระบบมาครอบ" (ไม่ใช่ห้าม — ต้องเป็นระบบที่ไม่ทำให้ช้าลง) |
| **โทย** | ❌ | **ลิเบอโร่ของครัว** — สั่งอะไรทำได้หมด แม้แต่มาเลี้ยงธาร่าที่บ้านให้นัททำงาน · ทำอาหารได้ดีพอควร | เหลาซิกที่สุดในครัว = ตัวเลือกดีสำหรับงานใหม่/งานทดลอง |
| **อ่องคิน** | ❌ | ผู้ชายคนเดียวในครัว | ⚠️ **จะถูกให้ออกในไม่ช้า** — ไม่ช่วยทำอะไร เข้ามาด้วยสิทธิ์เป็นแฟนอ่อง (ตอนนี้เลิกกันแล้ว) · แรงงานต่างด้าวย้ายงานในไทยไม่ง่าย → สถานการณ์ยากจะกลืน · **อย่าออกแบบระบบที่พึ่งคนนี้** |

### 🗣️ ภาษา — ตอบแล้ว (นัท 5 ส.ค.) · **ตัวกำหนดวิธีสร้าง tools ทั้งหมด**
- **ทุกคนเป็นไทใหญ่ (ฉาน/Shan)** — แต่ **เขียน/อ่านอักษรไทใหญ่ไม่ได้** สื่อสารกันเองใช้ **ทับศัพท์** ไปเลย
  → ⛔ **แปลเป็นอักษรไทใหญ่ = ไร้ประโยชน์** ต่อให้ AI แปลได้ก็อ่านไม่ออกอยู่ดี (ตัดทางนี้ทิ้ง)
- ✅ **พม่า = ช่องทางที่ใช้ได้จริง** — "พอได้" · มีอีก **2-3 คนอ่านพม่าได้ ช่วยกันอ่านได้** → เข้าถึงได้กว้างกว่าไทย (2 คน)
- **→ กฎออกแบบ tools ครัว:**
  1. ข้อความออก **ไทย + พม่า คู่กันเสมอ** (ไม่ใช่พม่าล้วน — อู/โม๋ข่องอ่านไทย)
  2. **พม่า = ตัวช่วย ไม่ใช่ตัวหลักที่พึ่ง 100%** ("พอได้" ≠ อ่านคล่อง) → ของสำคัญ (สูตร/ปริมาณ/จำนวนกล่อง) ต้องมี **ตัวเลข + รูป + ไอคอน** กำกับเสมอ
  3. ⚠️ **ห้ามให้ AI แปลสูตร/ปริมาณ แล้วส่งเข้าครัวโดยไม่มีคนตรวจ** — แปลเพี้ยน = อาหารพัง · ใช้ตัวเลข/รูปแทนตัวหนังสือทุกที่ที่ทำได้

### หลักการมอบหมายงาน (นัทสั่งเอง)
- **ประสานงานให้ทุกคนรับงานเท่ากันหมด** — ไม่กองที่ 2 คนที่อ่านไทยได้
- ⚠️ ตอนนี้โครงสร้างบังคับให้งานกองที่ อู/โม๋ข่อง โดยอัตโนมัติ (เพราะภาษา) → **tools ภาษา = ตัวปลดล็อกการกระจายงานให้เท่ากัน** ไม่ใช่แค่ของอำนวยความสะดวก

## ⏰ กำลังผลิตจริง — ทำไม Meal Plan ส่งเช้าไม่ได้ (นัทตอบเอง 5 ส.ค. · **ปิดคำถามค้าง P-track**)

> ❓ คำถามค้างเดิม: *"MP ล็อก จ/พ/ศ + บ่าย = ข้อจำกัดจริง หรือ default ที่ยืดหยุ่นได้?"*
> ✅ **คำตอบ: ข้อจำกัดการผลิตจริง — "ไม่ได้คือไม่ได้" · ห้ามผ่อนกฎ · ระบบล็อกไว้ถูกแล้ว**

**จังหวะเช้าของครัว (= ต้นเหตุ):**
| เวลา | เกิดอะไร |
|---|---|
| 08:00 | ครัวเข้างาน |
| ~09:00 | **ผักเพิ่งมาส่ง** |
| 08:00–09:00 | ครัว**ใช้วัตถุดิบเหลือจากวันก่อน**ทำไปพลางรอของ |

- **ทำสด + เมนูเยอะมาก** — ตัวอย่างจริง: ห้อง R&D วันนี้ต้องทำ **15 รายการ++** ในวันเดียว
- → ช่วงเช้า **กำลังผลิตยังไม่เต็ม** (ของยังไม่ครบ) = ส่งเช้าเป็นไปไม่ได้เชิงกายภาพ ไม่ใช่ข้อจำกัดของซอฟต์แวร์

### 🔑 root cause ที่แก้ได้จริง (ไม่ใช่ผ่อนกฎ)
> **ให้ผักมาส่งก่อน 06:00 ของ "วันก่อนหน้า"** → ครัวเข้างาน 8 โมงมีของครบทันที = ตัดช่วงรอทิ้งทั้งก้อน

**แต่จะทำได้ต้อง "แพลนงานผลิตล่วงหน้าได้"** → นี่คือ **งานของน้องนิว (production planning) + ฟ้า (ingredient planning)** โดยตรง
→ 🎯 **k-track เพิ่งให้เหตุผลเชิงธุรกิจกับน้องนิวที่ชัดที่สุดเท่าที่มีมา:** ไม่ใช่แค่ "assign เมนู" แต่คือ **ปลดชั่วโมงที่ครัวเสียไปกับการรอของทุกเช้า**

**⛔ ผลที่ต้องยอมรับ:** 4/18 ใบ (22%) ที่ Hato เคยรับ = **เรารับไม่ได้จริง** → parallel run ค้างที่ 13-14/18 = **ต้องแก้เกณฑ์ checkpoint ไม่ใช่แก้โค้ด**
