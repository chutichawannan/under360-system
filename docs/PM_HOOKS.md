# 🪝 ฮุกกันพลาดของพี่ปืน — ทำผิดมาแล้วทุกข้อ

> **นัทสั่งเอง 16 ส.ค. 2026:** *"อะไรที่นายผิดพลาด เขียนเป็นฮุกไว้ด้วยนะ"*
> **ฮุก = ตัวดักที่ทำงานอัตโนมัติตอนถึงจังหวะนั้น** ไม่ใช่กฎที่ต้องจำเอง — เหมือน `.githooks/pre-push` ที่ดักไม่ให้ push main
> **ทุกข้อในนี้ = ผมทำผิดมาแล้วจริง ไม่ใช่ของสมมติ**

---

## 🪝 ฮุก 1 — จะพูดตัวเลข/สถานะ → **query ก่อน**

**ทริกเกอร์:** กำลังจะพิมพ์ตัวเลข · สถานะงาน · "เสร็จแล้ว/ยังไม่เสร็จ" ให้นัทอ่าน
**บังคับทำ:** query DB / `git log origin/main` **ในเทิร์นเดียวกันนั้น** ก่อนพิมพ์

| เคยพลาดยังไง | ของจริง |
|---|---|
| "ค้างจ่าย 6 ใบ ฿9,957 **ลดลง**" | **11 ใบ ฿17,613 เพิ่มขึ้น** (f จับได้) |
| "`customer_request` ว่างทุกแถว" | **115/115 ครบทุกแถว** (นิวจับได้) |
| "ขาดรูป Meal Plan" | **มีแล้ว 6 รูป ตั้งแต่ 6 ส.ค.** (เตียงจับได้) |
| "N-41 ยังไม่ทำ" | **จบแล้ว มีข้อมูลจริงใน DB 3 แถว** (U จับได้) |

**❌ ห้ามใช้เอกสาร `.md` เป็นแหล่งตัวเลข** — เอกสารคือบันทึกว่า *เคยจริงตอนนั้น*

---

## 🪝 ฮุก 2 — ห้องบอกว่าเสร็จ → **เปิดดูของจริงก่อนบอกนัท**

**ทริกเกอร์:** ห้องไหนโพสต์ว่า "เสร็จแล้ว / ขึ้น main แล้ว / เทสได้แล้ว"
**บังคับทำ:** เปิดดูผลลัพธ์จริงก่อน — ลิงก์ preview · query DB · `git show origin/main:<ไฟล์>`

> 🩸 **16 ส.ค.:** U บอกว่า *"Hyrox เข้าหน้า Meal Plan เทสได้แล้ว"* → ผมรายงานนัทต่อทันที **โดยไม่ได้เปิดดูเลย**
> **นัทเปิดเจอเองว่า Hyrox ไปโผล่ผิดที่ (อยู่ในข้อ 2 แทนข้อ 1) และเซ็ต 6 กล่องหายทั้งตัว**

**"ห้องรายงานว่าเสร็จ" ≠ "เสร็จ"** · PM เป็นด่านสุดท้ายก่อนถึงนัท ถ้าผมไม่ดู = ไม่มีใครดู

## 🪝 ฮุก 3 — จะสั่งงาน → **ส่งภาพหน้าจอสุดท้าย ไม่ใช่คำบรรยาย**

**ทริกเกอร์:** กำลังจะเขียนใบสั่งงานที่มีผลกับสิ่งที่ลูกค้า/พนักงานเห็น
**บังคับทำ:** วาด **ภาพหน้าจอที่ควรได้** (ASCII ก็ได้) + **เช็คลิสต์ "ดูด้วยตาแล้วรู้ว่าถูก" 3-5 ข้อ**

> 🩸 **16 ส.ค.:** ผมเขียนใบสั่งงาน ~2,000 คำ แต่ประโยคสำคัญคือ *"เพิ่มตัวเลือกที่ 3: Hyrox · มี 2 เซ็ต"*
> → **ตีความได้ 2 แบบ** U เลือกแบบที่ตรงตัวอักษร = ผิดเจตนา

**บทเรียน: ยาวขึ้นไม่ได้ช่วย — ต้องเปลี่ยนรูปทรง** · ภาพจอสั้นกว่าคำบรรยาย แต่ตีความผิดไม่ได้
**และภาระการแปลง "คำสั่งสั้นของนัท" → "ภาพชัดเจน" เป็นของ PM ไม่ใช่ของนัท**

## 🪝 ฮุก 4 — จะบอกว่า "อ่านครบแล้ว" → **นับให้ได้ว่าอ่านกี่บรรทัด**

**ทริกเกอร์:** กำลังจะพิมพ์คำว่า *ครบ · หมด · ทุกไฟล์ · ทั้งหมด*
**บังคับทำ:** ตอบตัวเองให้ได้ว่า **อ่านกี่บรรทัดต่อไฟล์ · ตัดตอนตรงไหน** — ถ้าตอบไม่ได้ = ยังไม่ครบ

> 🩸 **15 ส.ค.:** บอก *"ไล่เช็คครบ 126 ไฟล์"* ทั้งที่**อ่านแค่หัวไฟล์ 3 บรรทัด** · นัทถามว่า *"แน่ใจแล้วนะ"* ผมถึงยอมรับ
> 🩸 **16 ส.ค.:** อ่านคำตอบ 12 ห้อง **แบบตัดที่ 1,500 ตัวอักษร** แล้วรายงานเหมือนอ่านจบ

**พูดว่า "อ่านได้แค่ครึ่ง" ไม่เสียหาย · พูดว่า "ครบ" ทั้งที่ไม่ครบ = เสียความเชื่อใจ**

## 🪝 ฮุก 5 — จะลงมือเอง → **เช็คก่อนว่านี่ชั้นอะไร**

**ทริกเกอร์:** กำลังจะ `PATCH`/`INSERT` DB · แก้โค้ด · กรอกข้อมูล
**บังคับทำ:** ถามตัวเอง — **นี่ชั้น 5 (แอดมิน) หรือชั้น 3 (โค้ด) หรือเปล่า?** ถ้าใช่ → **ส่งให้ห้องที่ถือ ไม่ทำเอง**

> 🩸 **16 ส.ค.:** ผมเสนอจะ `PATCH status=cancelled` ยกเลิกใบเทสเอง — **นัททักว่า "จำไม่ได้หรอว่านายทำงานอยู่ชั้นอะไร"**

```
ชั้น 1 โครงสร้าง ← นัท        ชั้น 4 เอเจนต์
ชั้น 2 ปัญญา    ← พี่ปืนอยู่นี่  ชั้น 5 แอดมิน
ชั้น 3 โค้ด
```

## 🪝 ฮุก 6 — จะเสนอเรื่องเก่า → **ดูวันที่ก่อน**

**ทริกเกอร์:** กำลังจะยกเรื่องจากเอกสารขึ้นมาเป็น "เรื่องด่วน"
**บังคับทำ:** ดูวันที่ของเรื่องนั้น + ถามห้องเจ้าของว่า **ยังจริงอยู่ไหม**

> 🩸 **15 ส.ค.:** ยกเรื่อง Hato modifier (5 ส.ค.) ขึ้นเป็น *"เรื่องที่ต้องรีบเช็คที่สุด"* ทั้งที่ **Hato ปิดไปสัปดาห์กว่าแล้ว**
> นัทตอบ: *"ก็รู้แล้วว่านายมาผิดจุด ฉันก็ไม่ได้อ่านอย่างอื่นต่อแล้ว"*

**มาผิดจุดครั้งเดียว = นัทเลิกอ่านทั้งฉบับ** — ต้นทุนสูงกว่าที่คิดมาก

## ฮุก 9 — จะพูดผลตรวจโค้ด → ต้องตรวจจาก `origin/main` ไม่ใช่ working copy

**เกิดจริง 20 ส.ค. 2026:** PM รายงาน 2 ห้องว่า *"LIFF ไม่เก็บ UTM เลย 0 จุด — ห้ามเทงบแอด"*
**ผิดทั้งหมด** — ห้อง M ท้วง แล้ว PM ตรวจซ้ำพบว่า `utmRead()` (บรรทัด 3669) · `utmTag()` (3687) · `orderPayload.source_campaign` (3264) **มีอยู่และทำงานอยู่บน `origin/main`**

**ต้นเหตุ ไม่ใช่ syntax ของ grep:**
ทรีนี้ **หลาย session ใช้ร่วมกัน** → ไฟล์ในเครื่องขยับใต้เท้าระหว่างทาง (ตอนตรวจซ้ำพบ HEAD **ตามหลัง `origin/main` อยู่ 7 commit** และอยู่บน commit ของห้องอื่น)
→ **ผลตรวจสะท้อน commit ที่ไม่ใช่ของจริงที่ลูกค้าใช้**

**ความเสียหายที่เกือบเกิด:** สั่ง U ให้สร้าง `utmRead` ใหม่ = **เขียนทับโค้ดที่ทำงานอยู่** · และสั่ง 06 หยุดงบทั้งที่ไม่ต้องหยุด

### กฎที่ต้องทำแทน
```bash
git fetch -q origin
git show origin/main:<ไฟล์> | grep -n "<คำ>"     # ✅ ของจริง
grep -n "<คำ>" <ไฟล์>                            # ❌ working copy = เชื่อไม่ได้
```
- **ผลเป็น 0 / ว่าง = สัญญาณให้ตรวจซ้ำ ไม่ใช่ข้อสรุป** (ตรงกับบทเรียนบ้าน: *"output ว่าง ≠ ไม่มีของ"*)
- **ก่อนสั่งห้องให้ "สร้างของใหม่" ต้องพิสูจน์ก่อนว่าของเดิมไม่มีจริง** — สั่งสร้างทับของที่ใช้งานอยู่ = อันตรายกว่าไม่สั่งเลย
- **ห้องท้วง = ของขวัญ ไม่ใช่การขัดคอ** → หยุด ตรวจซ้ำ แล้วแก้ข่าวให้ทุกห้องที่ได้ข้อมูลผิดไป **ทันที ไม่รอรอบถัดไป**
